## Requests for the integrator (Phase 2)
1. **Adapters for the module-local ports**, in `adapters/db/conversations.py` (D's adapter path) or a new `adapters/db/agent_data.py`. Signatures use only domain types and primitives, so they can be implemented structurally:
   - **`ConversationStore`**
     - `create`: `INSERT conversations(tenant_id=current_tenant, user_id, collection_ids) RETURNING id`.
     - `get` returns `(user_id, collection_ids)`.
     - `conversation_for_run`: a plain `SELECT conversation_id FROM pending_approvals WHERE run_id=$1 LIMIT 1`, with **no lock**. The runner then acquires the lease and calls `lock_pending`, in the same order a new turn uses.
     - `record_pending`: `INSERT … ON CONFLICT (conversation_id, tool_call_id) DO NOTHING`.
     - `decide_pending`: `UPDATE … SET status, decided_at=now()`. Also audit-log it, identifiers only.
     - `ConversationRuns.lock_pending` (D2) must return the run's rows in **every** status (not only `pending`): resume recovery reads `approved`/`rejected` rows (see "Resume semantics" below).
     - `claim_execution` (see request 2).
     - `summary`: `conversation_summaries.summary`.
   - **`KnowledgeBase`**
     - `collection_taus`: `SELECT id, tau FROM collections WHERE id = ANY($1)`.
     - `get_page`: live chunks of a document in the given collections, ordered by ordinal, as `RankedChunk` with `fused_score=0` and `rerank_score=None`.
     - `list_sources` and `sync_status`: JSON-safe rows with **no secrets** (never `config` or `secret_ciphertext`).
     - `remove_from_index`: one tx that inserts an `exclusions` row (ON CONFLICT DO NOTHING), sets `documents.deleted_at`, and writes `audit_log(actor, 'document.removed', document_id)`. rf_api already has these grants.
2. **Slot 0005 (additive, nullable):** `ALTER TABLE rf.pending_approvals ADD COLUMN executed_at timestamptz;`. Then `claim_execution` = `UPDATE rf.pending_approvals SET executed_at = now() WHERE conversation_id=$1 AND tool_call_id=$2 AND status='approved' AND executed_at IS NULL RETURNING 1` (true if a row was returned). It runs in the same tx as the side effect, which makes destructive tools exactly-once across node re-runs.
3. **Wiring (`bootstrap.py`, API container):** `LangGraphAgentRunner(AgentDeps(chat=OllamaChatModel…, retriever=…, embedders=…, runs=SqlConversationRuns…, tx=SqlTransactionManager…, jobs=…, conversations=<req 1>, knowledge=<req 1>, store=AsyncPostgresStore(pool), settings=AgentSettings(...)), checkpointer=FencedPostgresSaver(pool))`.
4. **Settings (`config.py`):** add `agent_default_tau: float = 0.35`, `agent_retrieval_k: int = 5` (8 for hosted), `agent_max_tool_rounds: int = 3`, `agent_strict_citations: bool = False`, `agent_verifier_trusted: bool = True` (set False for models below the verifier SLO, ADR-0012), and `agent_summarize_after_messages: int = 20`. Map these into `AgentSettings`.
5. **Worker job kind `summarize_conversation`:** `finalize` enqueues it (priority `maintenance`, `payload={"conversation_id"}`, `dedupe_key="summarize_conversation:<id>"`) once history passes the threshold. Worker dispatch is Phase 2. D2 already asked for rf_worker SELECT on the checkpoint tables.
6. **Packaging:** `prompts/templates/*.md` must ship in the wheel. Hatch includes non-.py files under `src/ragforge_core` by default; please check the built image. `prompts` fails at import if any header is missing.
7. **No new dependencies.** D1 uses langgraph, langchain-core and pydantic, all already in the `agent` extra and core deps. The API image needs the `agent` extra.

## Contract notes for E (API)
- **Tool-result citations `[T<n>]`:** besides `[S<n>]`, RAW answer text may contain `[T1]`, `[T2]`... meaning "from the n-th tool result of this turn" (sync status, list of sources, the outcome of an approved removal). They have no `TurnCitation` (no page to link). Please strip them, or render them as a non-link marker, in the sanitizer/UI the same way `[S<n>]` labels are handled.
- **Conversation scope:** a follow-up's `collection_ids` must be a subset of the conversation's stored collections (it may narrow, never widen or switch); anything else is `ValidationFailed` (422) before the lease is taken. An empty list means the stored scope. A different scope is a new conversation.
- **Event order:**
  - `TurnSources` comes after every retrieval (graph or `search_notes`/`get_page`), before any text that may cite it.
  - Then `TurnText` (RAW deltas), `TurnToolCall`, then either `TurnInterrupt` (terminal; **no `TurnDone`** follows) or `[TurnReplace] → TurnCitation* → TurnVerification → TurnDone`.
  - A strict regeneration is **not streamed**. It arrives once, as `TurnReplace`, after it passes verification.
- **Verification semantics:**
  - Grade abstain: `TurnText(abstain)` + `verified`. The text is server-authored from hits; no model claims.
  - Abstain after a failed regeneration: `TurnReplace(abstain)` + `unsupported` with no claims.
  - `unverified` appears when `verifier_trusted=False`.
  - Claims are always verbatim substrings of the RAW answer.
- **Errors raised by `run_turn`/`resume`** (all before the first event, except `LeaseLost`): `Forbidden` (scope `chat`, or `approvals:write` for resume), `ValidationFailed`, `NotFound` (conversation or run not visible or not owned), `TurnInProgress`, `Conflict` (approvals no longer pending), and `LeaseLost` (mid-stream).
- **Cancellation:** `aclose()` on the iterator cancels the running node, closes the model stream, releases the lease and discards the draft. Nested generators are closed explicitly, so this happens synchronously.
- **Decisions:** values may be `ApprovalChoice` or the strings `approve`/`reject`. Pending calls the client omits are **rejected**. Unknown ids → 422.

- **Lease timing:** the lease is released *before* `TurnInterrupt`/`TurnDone` is yielded, so E may resume or send a follow-up the moment it forwards the terminal event.
- **Resume semantics:** the runner takes the lease, reads the checkpoint, and only then locks and decides the rows. Any failure before the graph starts releases the lease. A resume can also recover from a crash:
  - If an earlier resume decided the rows but died before the graph ran, retrying (with the same or no decisions) re-applies the recorded decisions. Asking for a different decision → `Conflict`.
  - If an earlier resume died inside `execute`, retrying continues from the checkpoint. The execution claim keeps each side effect exactly-once.
  - A crash after `execute` finished (for example during the following `generate`) is not resumable. The user sends a new message.
- **`prompt_version`:** this is `PROMPT_VERSION` when one build served the whole turn. When a resume is served by a newer deploy, it is the distinct versions joined with `" + "` (e.g. `"<old> + <new>"`). Group on the exact string.
- **Memory placement:** long-term facts (each shown as `[fact:<12-hex>] quote`) and the LLM-written rolling summary are fenced **user-side data** in the packed question, never in the system prompt. `forget_fact(fact_id)` accepts that 12-hex id (also as `[fact:…]`) or a full sha256 key. A short id resolves only against the facts shown to the model in that turn, and deletion always happens in the Principal's namespace.

## Contract for ChatModel adapters (D2 / Phase 2 hosted)
- Structured tool messages (`Role.tool`, assistant `tool_calls`) are only sent **together with a non-empty `tools` list**. When the agent unbinds tools (after `max_tool_rounds`, and for the strict regeneration), it flattens earlier tool exchanges into plain assistant/user text, keeping the `<tool_result>` fence. This is what Anthropic-style APIs require. Adapters don't need to handle the "tool blocks without tools" case.
- Consecutive messages with the same role can occur, for example a packed question followed by a flattened tool result. Adapters for providers that need strict alternation should merge them.

## Contract with D2 (checkpointer)
- Config is `{"thread_id": str(conv), "rf_tenant_id": UUID, "rf_run_id": UUID}`, passing UUID objects as D2 asks. The key names are duplicated in `agent/runner.py` (`CONFIG_TENANT_ID`/`CONFIG_RUN_ID`) because agent can't import adapters. I support D2's proposal to move them into `domain`.
- The runner uses `durability="sync"`, so a lost lease fails before the next node and `TurnDone` is only sent after the final checkpoint has persisted.

## Port observations (no frozen port changed)
- `ConversationRuns` has no way to insert, decide or claim approvals, hence the module-local `ConversationStore`. Proposal for a future revision: fold `record_pending` / `decide_pending` / `claim_execution` / `conversation_for_run` into `ConversationRuns`.
- `Retriever` exposes no collection τ, hence `KnowledgeBase.collection_taus`.
- **LangGraph gotcha:** `Command(resume=dict)` is read as an `{interrupt_id: value}` map when every key looks like an xxh3-128 hex digest. Tool-call ids (uuid4 hex) match that pattern, so the runner wraps decisions as `{"decisions": {...}}`. The resume tests cover this.

## Known gaps
- Context trimming is by message count (`history_messages`), not tokens.
- The verifier eval-set measurement (ADR-0012) isn't part of this module.
- `forget_fact` deletes from the store (own pool) while the claim tx holds that one `pending_approvals` row lock: two single-row store round trips. Kept on purpose: claiming in a separate tx first makes a crash before the delete at-most-once (reported as done but not done), and deleting before the claim runs the effect before the `status='approved'` gate. The lock is uncontended (only this run's lease holder touches those rows). Delete is idempotent, so a commit failure after it is at-least-once with the same outcome.
- **Heartbeat cost (round 3):** the pure nodes `grade`, `verify_citations`, `decide` and `abstain` no longer heartbeat (5 lease round trips for a plain turn instead of 8); the background keepalive and the fenced checkpointer still cover them. Measure the remaining per-node cost against the TTFT budget in M4.
- **Lease robustness (round 3):** a failed background heartbeat is logged and retried (it no longer kills the keepalive), and `_Release` never raises an Exception: a keepalive/release failure is logged and the terminal `TurnDone`/`TurnInterrupt` is still sent (the lease then expires on its TTL). Log events: `agent.lease_heartbeat_failed`, `agent.keepalive_failed`, `agent.lease_release_failed` (identifiers only).
- `forget_fact` can only reach facts shown in the turn's `<facts>` block (the newest `memory_facts`, default 20) or a full key. Listing older facts would need a `list_facts` tool in Phase 2.
- Round-3 full-suite run: 884 passed, 0 failed. mypy --strict is clean on every D1 source and test file.
