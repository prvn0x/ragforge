# Module E1 handoff: streaming output sanitizer + GFM fuzz oracle

**Owner paths:** `packages/core/src/ragforge_core/agent/sanitize.py`, `packages/core/tests/module_e1/**`
**Migration slot:** none.

## What exists

`ragforge_core.agent.sanitize.MarkdownStreamSanitizer` implements the frozen `OutputSanitizer` port
(`allow(urls)`, `feed(text) -> str`, `finish() -> str`). It is the ADR-0011 incremental state machine
(Text / Fenced code / dropped reference-definition line), with inline code, constructs (`[`, `!`, `<`,
line-start `[`) and bare URLs held inside a bounded 512-char window.

Also public: `normalize_url(url) -> (match_key, fragment) | None`, `HOLD_LIMIT`, `IMAGE_REMOVED`,
`BARE_URL_PATTERN`.

## Decisions the reviewer should know (all fail safe)

- **Why the text is inert.** In Text state, every model `[`, `]`, `<`, `!` and `&` is
  backslash-escaped. A lone `\` becomes `\\`, so it can never escape a character we emit next. The
  renderer can't form a link, image, definition, autolink, raw HTML or entity from our text. Every
  explicit link in the output is one this module wrote, with the stored canonical href.
- **Bare URLs are checked on the joined word, not per run** (round-1 P0). A construct that emits
  nothing (dropped `<javascript:x>`) or whose text is re-scanned (a dropped link) used to leave two
  runs touching in the output, so `ww<javascript:x>w.evil.example` rendered as
  `www.evil.example`. The sanitizer now keeps the decoded text of the current *joined word*
  (`_tail`). It is reset by every other emission, because each one is whitespace, a code span, a
  link, or ends in `[ ] < ! |` or a backtick, and no URL pattern contains those chars. Each run is
  matched as `tail + run`. If the URL starts in already-emitted text, the whole run is defanged into
  a code span, which ends the word. Output: `ww\`w[.]evil[.]example\``. A joined word longer than
  512 chars is no longer tracked; every further joined run is defanged until the word ends.
- **E-mail and `mailto:` are matched Unicode-aware** (round-2 P1). linkify links `a@évil.com`,
  `a@evil.рф`, `me@例え.jp`, `mailto:;@evil.example` and even dotless `mailto:a@b`, which the old
  ASCII e-mail pattern missed. Now any `mailto:`/`xmpp:` (any case) and any `@` followed later in
  the word by a `.` (local part optional, any non-space chars) is defanged. The `@` itself
  triggers, so the joined-word guard cannot be bypassed via chars emitted before the word. Cost:
  prose like `foo,https://user:pw@docs.example.com/guide` is defanged instead of linked; `me@home`
  and `user@host` (no dot, no `mailto:`) stay plain text because neither GFM nor linkify links them.
- **Large feeds are windowed** (round-2 P2). Dropping a link rebuilds the working buffer, which
  used to copy the whole rest of a big `feed()` per link (quadratic). `feed()` now moves input into
  the buffer 2048 chars at a time, so each rebuild copies a bounded buffer. Because output is
  chunking-invariant, the windowing cannot change the output (tested across window edges).
- **`//` is defanged** (round-1 P1). linkify's protocol-relative schema links `//host`, including
  after `http&#58;` or a fullwidth colon that no scheme rule sees. Any `//` in a word is defanged.
  The cosmetic cost: prose like `a // b` shows `//` as code.
- **Bare-URL detection uses the decoded text.** Backslash pairs are resolved first, so
  `www\.evil.com` and `http:\/\/x` are still caught. Entities never decode because `&` is escaped.
- **Scanning is linear** (round-1 P2). Two guards keep `[` floods from costing 512 steps each:
  1. A `[` is scanned only when a `](` exists before the line ends inside its window. This uses a
     C-speed `str.find`, and it short-circuits only when the window is fully decided.
  2. Completed scans whose range contains a `](` draw on a credit:
     `64*512 + 8 * stream position` steps. When the credit runs out, `[` and `![` become plain text.

  Only completed scans are charged, and a decided precheck implies "no `](` in range", so the
  credit (and so the output) is the same however the input is chunked. That is tested. Normal
  prose never comes near the credit: 2000 paragraphs with citations and links keep every allowed
  link, which is also tested.
- **Allow-list matching (ADR-0011 clarification requested).** The match key is scheme +
  lower-cased host + non-default port + path + **query**. Credentials are stripped and the fragment
  is ignored. Including the query is stricter than the ADR's wording (scheme/host/path), on
  purpose: two hits can share a path and differ only by query (`/view?id=1`, `/view?id=2`), and a
  path-only key would make one citation silently link to the other hit. The cost is fail safe: a
  citation the model writes without the stored query (or with extra tracking parameters) is
  dropped to plain text. **Integrator:** please record this in ADR-0011 ("normalized URL = scheme,
  lower-cased host, non-default port, path, query"). If product prefers recall, the cheap
  alternative is a second, path-only index used only when the path maps to exactly one stored
  URL; it is still safe because the emitted href is always the stored URL. The emitted href is always the stored canonical URL. A fragment from the
  model is carried over only if it matches `[A-Za-z0-9_-]{1,128}` and the canonical URL has no
  fragment of its own. `allow()` ignores non-http(s) URLs and URLs containing whitespace or control
  characters.
- **All images are removed**, relative ones too, because a relative `src` is still a fetch against
  the client's origin. Reference-style images and links become literal text.
- **Inline `javascript:`, `data:` and `vbscript:` links** are dropped and their text kept.
  Autolinks with those schemes are dropped entirely; the joined-word guard covers the gap they
  leave. Non-allow-listed autolinks are rescanned as bare URLs, so they come out defanged.
- **Fences.** A fence opens only at column 0, with no open container, on a valid CommonMark opener.
  Lines with a `|` count as containers too, because markdown-it's table rule swallows a column-0
  fence line as a table row. A fence-looking line we decline is escaped. The cost: code fences
  inside lists or blockquotes render as text.
- **Inline code containing `|`** is escaped instead of passed through verbatim, because GFM tables
  split cells at pipes even inside code spans. **Two adjacent code spans** get a space between them.
- **Latency.** Each word is held until its delimiter (one word of latency). Constructs are held for
  up to 512 chars. Fenced code is never held.
- **Chunking can't change the output.** Every decision depends only on the input, so any split
  produces byte-identical output. This is property-tested.
- **CR/CRLF are normalized to LF**, and NUL becomes U+FFFD. `feed()` after `finish()` raises
  `RuntimeError`, and a second `finish()` returns `""`.

## Tests (`packages/core/tests/module_e1`, 203 tests, about 25 s)

- `test_e1_fuzz.py` covers grammar-based hostile markdown: container nesting with fences, fence
  length/char/indent/info mismatches, info strings containing backticks, padding around the 512
  boundary, reference/inline/autolink/bare URLs, HTML, entities, escapes and tables. It also has
  **splice productions** (new): a URL/www/e-mail/`//` token cut at random offsets with dropped or
  rewritten constructs inserted (`<javascript:x>`, `<data:x>`, `[](javascript:x)`,
  `[w](http://evil)`, `[x][r]`, escapes, entities, comments, images, definition lines), and
  splicers between arbitrary children. Inputs are split at random token and char boundaries, and
  **every prefix** of the stream is checked against the AST oracle. Mutation check: with the
  joined-word guard disabled, the grammar finds a bypass immediately
  (`/<javascript:x>/evil.example/x` -> `//evil.example/x`).
- `test_e1_corpus.py` holds about 100 exfiltration payloads, each fed whole, char by char and in two
  stride splits. That includes all five round-1 P0 reproductions, more splice variants, and
  `//host`, `http&#x3A;//` and fullwidth-colon cases. There are also exact-output checks for each
  ADR rule.
- `test_e1_units.py` covers port conformance, the 5000-char fence round trip, fence rules, holding
  and latency, allow-list normalization, lifecycle, CRLF, and **CPU bounds** (new). Five flood
  shapes (200 KB `[`, `[...](x)` blocks, nested rewrites, bracket lines, `![` floods) and a 1 MB
  single-feed dropped-link flood must each finish under 5 s. Measured: 0.1-0.6 s each, where `[` floods used to take 22 s. The credit is
  tested for chunking independence, and for never starving normal prose.
- Oracle note: `MD.parse` always gets `markdown + "\n"`, to work around a markdown-it-py 4.2
  `IndexError` on blockquoted tables with no trailing newline.

## Known gaps

- Schemeless domains (`evil.example/x`) aren't defanged. GFM doesn't autolink them, but linkify's
  `fuzzyLink` does (see request 3).
- The oracle skips bare-URL checks for text inside a validated link, because GFM and markdown-it
  never autolink inside a link.
