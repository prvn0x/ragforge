# Handoff P2B-AG: answer path (ADR-0015)

Module AG made retrieve → answer the designed default, added explicit-action routing, small-model citation prompts, lenient citation parsing and server-inferred citations. The decision and the exact status rules are in `docs/adr/0015-retrieve-then-answer.md`. This file lists only what AG needs **outside its owned paths**.

## What changed inside AG's paths (for reviewers)
- **New modules:**
  - `agent/actions.py`: deterministic intent detection and `tools_for_turn`;
  - `agent/attribution.py`: lexical/verbatim attribution and `settle`, the status rules;
  - `agent/coverage.py` (coverage redesign): segmentation, the closed allowlist and `residue`, the single definition of what `verified` guarantees;
  - `agent/structure.py` (round 4 of the redesign's review): the ONE structural map of a text (an answer or a source page) from a markdown-it-py CommonMark parse, with source positions; `coverage`, `citations` and `attribution` read only this.
- **`agent/citations.py`:** `normalize_citations` (lenient → canonical labels; validity is still decided by `check_citations`).
- **`agent/grounding.py`:** `GroundResult.conclusive` (False when the verifier never produced a valid verdict).
- **`agent/settings.py`:** `ToolMode` (`actions` default, `always` override) and `AgentSettings.tool_mode`. `ToolMode` is exported from `ragforge_core.agent`.
- **`agent/state.py`:** new per-turn fields `action`, `inferred` and `normalized`, all reset by `runner._turn_input`. Old checkpoints read them with defaults. (`uncited_claims` and `has_claims` were removed by the coverage redesign; a checkpoint that still holds them loads fine, checked with LangGraph's in-memory saver.)
- **`agent/nodes.py`, `graph.py`, `runner.py`:**
  - binding goes through `tools_for_turn`;
  - action turns skip the weak-grade abstain;
  - `verify_citations` normalises and attributes, and `ground_check` settles;
  - `finalize` emits `TurnCitation(inferred=True)` and sends `TurnReplace` when normalisation changed a streamed draft.
- **Prompts:** `answer@6` (coverage redesign; `answer@5` in round 5), `answer_strict@4`, `actions@2` (tool-calling step) and the new `action_reply@1` (the reply step of an action turn). `PROMPT_VERSION` therefore changes.
- **Round-1 review fixes:**
  - `GroundResult.located`, and a closed claim-level gate on unlocated verdicts;
  - ADR rule 4a: an inconclusive verifier keeps the answer as `partial` with no citation;
  - narrow destructive phrasings;
  - server-built calls for `/remember`, `/forget`, `/sources`, `/sync` (`actions.server_call`, state field `command_calls`);
  - action replies are never page-attributed;
  - no "see/cf." citation cue.
- **Round-2 review fixes:**
  - one citation parser for the check and attribution (then `citations.has_label` / `stray_fragments`; both deleted in the parser rewrite's review round 2, the check now reads `coverage.segment` and `citations._stray_spans`): a malformed citation-shaped fragment (`[S2, S10000]`, `[1, S2]`, `(S1-S3)` mid-sentence) is an invalid label; label ranges `[S1-S3]` are expanded (at most 8) and then checked;
  - the verifier sees inferred pairings as `[S<n>]` (`attribution.annotate`, prompt `ground_check@3`); its claims are mapped back onto the client's text;
  - ADR rule 4a (inconclusive/unlocated verifier, no citation survives) is now **`unverified`**, not `partial`;
  - action turns never run `contextualize` (follow-up `/remove X` retrieves "X", one model call less);
  - sync phrasings anchored to the user's own sources (Kafka/DB replication questions are no longer actions).
- **Round-3 review fixes (claim-detection parts superseded by the coverage redesign below):**
  - "claim" is separate from "attributable": any sentence with a digit or a non-connective content word is a claim (Unicode-aware tokenizer, list markers ignored); a claim too short to attribute is uncited and highlighted. "The port is 9093." and an all-CJK answer can no longer reach `verified`. `MIN_CLAIM_TOKENS` is gone;
  - bare `[n]` is normalised only at a clause end ("list [1, 2] in Python" stays prose);
  - server-built commands (`/sync`, `/sources`, `/forget <id>`, `/remember <words>`) skip retrieval (`graph.after_memory`);
  - ADR §5 documents why `strict_citations=True` bypasses attribution.
  - Eval note: short correct sentences now show as `partial` (uncited) instead of being ignored; the A1 re-run should report that share separately.
- **Round-4 review fixes (no P0/P1 were open; all six P2s addressed in code or routed below; claim-detection parts superseded by the coverage redesign below):**
  - action false positives closed: `_PAGE` no longer accepts doc/document, "… from my/the index" must end the message, sources is end-anchored, forget must name a *fact*; the reviewer's exact strings are in `test_questions_are_not_actions`;
  - a bare remember phrasing with "?" never binds the `remember_fact` write (only "can you remember that …?" and `/remember` do);
  - polarity: "No." / "Yes, it does." are claims; a polarity-only sentence is attributed with its adjacent claim (`attribution.claim_units`), so a bare yes/no answer is `unsupported` (rule 2) and can never be `verified` without a citation; the hypothesis property covers it;
  - ADR rule 7: with `verifier_trusted=false`, `finalize` emits no inferred citation and highlights those sentences (model labels still shown); tested end to end;
  - number check: each number must share a neighbouring content token with the same number in one source sentence (catches "3 partitions" vs "3 brokers");
  - measured offline: `actions.detect` fires on 0 of the 30 eval questions (recorded in the ADR).
- **Round-5 review fixes (one P1, five P2s; claim-detection parts superseded by the coverage redesign below):**
  - P1, fail closed: a sentence is exempt from being a claim only when it is RECOGNISED as stating nothing (connective/meta text whose every clause names a connective word, a refusal, a whole-sentence closing pleasantry, a wordless fragment). "It does.", "Both.", "Only once.", "In short, it does." are claims. Backstop `attribution._needs_provenance`: an answer with no claim sentence still needs provenance unless it is a refusal, so a non-refusal answer with no surviving citation can never be `verified`. The hypothesis property now also generates function-word sentences (it fails on the round-4 build);
  - pleasantries: `answer@5` says "do not add greetings or offers of further help"; a closed whole-sentence list ("Let me know if you have other questions.", "I hope this helps.") is not a claim; never matched by word;
  - clause-end "(S3)" after a product name (same token, Amazon/AWS run, or an acronym definition such as "Simple Storage Service (S3).") is left as prose;
  - the command word must end at whitespace, ":" or the end ("/sources/foo", "/remove/tmp" are questions);
  - a remember phrasing followed by a second request ("keep in mind that X, how does vacuum work") is a question;
  - new default-mode test: `/forget <id>` (server-built), approve, crash in execute, resume: deletes exactly once, reply under `action_reply@1`.
- **module_d1 tests:** updated only where they encode the old default, each with a comment.
  - `d1_fakes.make_harness` uses the production default (`ToolMode.actions`) and takes a `tool_mode` argument.
  - The 28 D1 test functions (30 cases) that reach tools through an ordinary question pass `tool_mode=ToolMode.always`. Each of their files has a comment saying why. The other 70 D1 cases run on the shipped default.
  - Three tests that pass their own `AgentSettings` add `tool_mode=ToolMode.always`.
  - `answer@3` → `answer@4` (then `answer@5`, round 5; now `answer@6`, coverage redesign) in one assertion, and `ground_check@2` → `ground_check@3` in the same test (round 2: the verifier prompt now checks each `[S<n>]` pairing).

- **Coverage redesign (after review round 5; replaces the claim-detection machinery):**
  - **The guarantee is now an allowlist.** `verified` ⇒ the residue is empty, where the residue is the whole answer minus (a) text a valid model label covers (only back to the previous boundary), (b) units whose inferred citation passed the ground check, and (c) a closed allowlist (pleasantries and three lead-ins, whole-sentence refusals, markdown structure, punctuation and emoji). Residue with a letter, digit or code is never `verified`, and it is highlighted verbatim. The exact rules are ADR-0015 sections 4 and 5;
  - **deleted:** `is_claim`, `claim_units`, polarity joining, the connective/polarity/refusal vocabularies and `_needs_provenance`;
  - **a pure refusal** (refusal +/- pleasantries, labels ignored) is `unverified`, and its ground check is skipped (`graph.after_citations` sends only `pending` drafts to the verifier: one model call less);
  - **attribution only proposes:** it now also refuses a candidate for a negation its best source sentence lacks, and attributes code blocks only verbatim;
  - **fence lines are strict:** text on a fence line other than a known language tag makes it a normal line. The property test found prose riding on a quoted code block through the closing fence line;
  - **`answer@6`:** "a label covers only its own sentence; put a yes or no in the same sentence as the fact". A standalone "Yes." is now residue (`partial`), which is the main recall cost;
  - **tests:** new `module_ag/test_ag_coverage.py` holds a hypothesis property with its own residue oracle and an always-"supported" verifier stub; every attack from the previous review's script as a regression; and happy-path recall tests. `test_ag_attribution.py` was rewritten for the new API, and `test_ag_turns.py` gained end-to-end tests for tails after a label, refusals and yes/no;
  - **mutation check (done, then reverted; the source was diffed back to identical):** five deliberate breaks of `coverage.py` were each caught by the property alone:
    - text after the last label inherits that label;
    - code is never residue;
    - only an upper-case start begins a sentence;
    - the refusal allowlist is matched as a prefix;
    - residue counts only units with a digit;
  - **property runs:** 1,500 examples per run, plus 90,000 in stress runs, with no failure on the final build;
  - **module_d1:** one more assertion changed, `answer@5` → `answer@6` in `test_d1_turns.py` (prompt version), with a comment.

- **Coverage redesign, review round 1 (scored 7.5; two P1s, six P2s; all fixed by making coverage stricter, no word rules added to the guarantee):**
  - **P1, segmentation fails closed** (`coverage.sentence_ends`): a sentence ends at every Unicode `Sentence_Terminal` character (Unicode 15.0 PropList, generated into a literal table and united with every punctuation character named like a sentence end, plus ellipsis/dot leaders/Greek question mark/Tibetan shads), whatever follows it. Only a dot inside a token (digit.digit, lower.lower) and the last dot of "e.g."/"i.e." are exempt. A test rescans `unicodedata` for missing terminators. Beyond the review: AG's own probing found "NASA built Kafka in 1850;Kafka stores records [S1]." still `verified`, so a semicolon in any script now ends a clause too (two more `ATTACKS`, a generator case, mutant C11). Colon, comma, dash and parentheses deliberately do not cut (ADR "accepted residuals");
  - **P1, token-aligned code attribution** (`attribution.verbatim_source`): every line must occur in one source as a whole-token sequence (a number is one token with its decimals), and a block needs at least 3 non-trivial tokens. "port is 9", "runs every 6", "is 3" and "a / b / c" get no candidate;
  - **P2, numerals:** a numeral is a list marker only in an actual numbered list (1 starts one, n follows n-1); "(7)", "7)", "b)" and an out-of-sequence "42." at the start of a line or sentence are cut off as their own unit (residue);
  - **P2, bare labels:** a label run with no words cites the unit before it only on the same line (gap of whitespace/terminators/closers), on the next line of the same plain paragraph, or on the line right after a code block; otherwise it is an orphan that covers nothing but is still validated. *Deviation from the suggested fix, on purpose:* the next line of the same plain paragraph is allowed, because Markdown renders "claim.\n[S1]" as one paragraph (the reader sees the label next to the claim) and "Source: S1" on its own line is a form the lenient parser accepts. A blank line, a rule, a list/quote/heading marker, or an emoji in between still makes it an orphan;
  - **P2, hidden labels:** new `agent/labels.py` holds the canonical marker and `mask_hidden` (inline code and HTML comments blanked, offsets kept); coverage, `check_citations` and the stray-fragment rule look for labels only in the masked text;
  - **P2, one segmenter:** `check_citations` (rule 1 and strict mode) iterates `coverage.segment`; stray fragments are found per prose line and mapped to the units they overlap; normalisation rewrites only `coverage.prose_lines`; attribution splits source pages with `coverage.sentences`. The old `_SENTENCE_END`/`_LEADING_CITATIONS`/`_FENCE` machinery is deleted. `sentence_spans` stayed then as a thin view of the prose units for `module_d1/test_d1_units.py` (deleted in the parser rewrite's review round 2; that test now reads `coverage.segment`). Strict mode now flags a tail after a label as its own unit, and no longer flags an allowlisted pleasantry/refusal;
  - **P2, the property:** new oracle with its own terminator set (a `unicodedata` scan), cuts with or without whitespace, character-level coverage, CommonMark fences; the generator adds no/zero-width/no-break separators, `… । ． ｡ ؟ 。 ."`, enumerators, orphan and next-line labels, rules, `~~~` and tagged fences, a mismatched closer, truncated code, inline-code and HTML-comment labels, Devanagari, signed numbers and negating verbs. Five fixed `@example`s pin the round-1 shapes. The stress run found one oracle bug (kept spans were matched non-overlapping), fixed;
  - **property runs (final build):** 1,500 random + 5 fixed examples per test run; a 100,000-example stress run passed (12,489 `verified`, 45,602 `partial`); the citation property passed 3 x 10,000 stress examples (its own stress run found, and AG fixed, a non-overlapping span lookup in that test);
  - **P2, numbers and negation:** a number keeps its sign, decimals and thousands separators; "fail(s/ed)", "lack(s/ed)", "refuse(s/d)" and "unable" negate. These only withhold candidates (fail closed) and are not part of the guarantee; the ADR says so;
  - **regressions:** all 30 inputs of the review are in `ATTACKS` (plus the two semicolon joins). Run against the previous build (its three source files swapped back in, then restored byte-identical), exactly those 30 reached `verified`; on this build all 118 attacks hold;
  - **mutation check (done, then reverted; diffed identical):** eleven breaks of coverage (tail inherits the label; code never residue; terminator needs whitespace; ASCII/CJK-only terminators; bare label attaches across anything; labels in inline code/HTML comments count; enumerators never cut; every numeral is a marker; refusal as a prefix; digit-only residue; semicolon does not cut) were each killed by the property at its default size, again by random generation alone (3,000 examples, no fixed examples), and by `test_review_attacks`. Two attribution breaks (raw-substring code matching; numbers without sign/decimals) survive the property by design (the oracle takes kept units as given) and are killed by `test_review_attacks`;

- **Coverage redesign, review round 4 (the structure must rest on a real CommonMark parse, not regexes):**
  - **one structural map** (`agent/structure.py`): markdown-it-py, CommonMark preset with raw HTML recognised, GFM `table` and `strikethrough` enabled, `linkify` enabled only when `linkify-it-py` is importable (fuzzy links off), `text_join` disabled. It yields every code element at any depth (fenced/indented blocks, also in blockquotes and list items; inline spans of any backtick count), links (destination/title hidden), autolinks and linkified URLs, images, inline and block HTML, strikethrough, breaks, escapes, entities and the visible text runs, with source positions. Inline tokens have no offsets in markdown-it-py, so each inline content is aligned onto its source lines and each child onto the content, in order, every step checked (text must equal its source; link extents recomputed with markdown-it-py's own `link`/`image` rules run silently; code spans closed by the first backtick run of the opener's length). Any mismatch makes the part opaque. Unclaimed text that says something becomes an opaque unit (reference definitions, cells beyond the header, numerals of a list not starting the count).
