## Contracts other modules rely on
- **Anchors** are the dashless 32-hex Notion block id. Deep link = `f"{external_url}#{anchor}"` (`ids.deep_link`). `external_id`, `links_to` and `synced_source_ids` use the canonical dashed UUID.
- **`fetched_at`** = `Date` of the first response (`GET /pages/{id}`) minus 60 s. If Notion sends no Date header, the fetch fails with `NotionProtocolError` (retryable). It never falls back to our own clock.
- **Errors**: `NotionPageGone` (trashed, or a 404 with Notion's `object_not_found` code during fetch), `ValidationFailed` (malformed `external_id`: permanent, use `fail(..., permanent=True)`), `UpstreamRateLimited(retry_after_s)` (a Retry-After over 60 s, retries used up, OR the shared bucket's debt exceeds the limiter's `max_wait_s` because another worker hit a long Retry-After: pass it to `JobQueue.fail(retry_after_s=...)`), `NotionApiError` / `NotionTransportError` / `NotionProtocolError`. No error, repr or log line carries the token, and nothing reachable from them does either: `__cause__` and `__context__` are None on wrapped httpx/decode errors, and the Authorization header is stripped from `response.request` once a response arrives (so traceback locals captured by Sentry/rich hold no token).
- **RateLimiter keys** are `limiter_key(token)` (`"sha256:<hex>"`), never the token. `integration_key(limiter_key(t)) == sha256(t)`, so the `notion_rate` row is the one ADR-0007 names. Any other implementation/wrapper of the port only ever sees the digest.
- **`confirm_deleted`** returns True only for a 404 whose body has `code: object_not_found` (deleted or unshared), `in_trash` or `archived`. A 401, 403, 429, 5xx, any other 404 (proxy HTML, wrong route), transport error or malformed id returns False, so neither a revoked token nor a misrouted request can tombstone a workspace.
- **Data-source rows** become documents with `metadata["properties"]`, plus a leading `**Name:** value` paragraph (anchor = page id). `metadata["notion"]` holds parent info. `metadata["unsupported_blocks"]` holds `{type: count}`. `metadata["truncated_depth"]` is set when the depth limit (10) cut the tree. `metadata["truncated_properties"]` (sorted names) is set when Notion's page object cut a relation/people/rich_text/title value at 25 items (`has_more`); the stored value and the relation `links_to` edges are then partial. Paging `GET /pages/{id}/properties/{prop}` is a possible Phase 2 follow-up (extra rate budget per row).
- **links_to** also includes inline text hyperlinks to Notion pages (`notion.so`, `*.notion.site`, relative `/<id>`; `?p=` peek ids win over the path). A link that targets a bare block id (rare) yields an edge to a non-document id; resolvers should ignore unknown targets.
- **Table anchors**: the first row group of a split table anchors on the table block; each later group anchors on its own first `table_row` block (header still repeated).
- **Connector config keys** (module C writes them at connect time; routing reads them): `config.integration_id` (the Notion bot id) and `config.workspace_id`.

## Requests for the integrator / other modules
1. **Sync service (C2 / bootstrap):** `SyncDeps(connectors=NotionConnectorFactory(PostgresRateLimiter(worker_engine)), ...)`. `open(...)` validates eagerly (wrong `kind`, non-UTF-8 or empty token -> `ValidationFailed`, permanent, no request made) and returns an async context manager that opens one `NotionClient` per run and always closes it.
2. **Overlap: single owner = the connector (C1 spec, ADR-0007). C2 currently ALSO subtracts 5 min** (`services/sync/policy.py: listing_since(cursor, cursor_overlap)`), so the effective overlap today is 10 min: correct (freshness skips re-listed pages) but it costs rate budget. Decision requested from the integrator, pick ONE of these one-line changes: (a, preferred) C2 sets `SyncPolicy.cursor_overlap = timedelta(0)` / passes the cursor straight to `list_changed`; or (b) bootstrap builds `NotionConnectorFactory(limiter, list_overlap=timedelta(0))`. Please mirror the decision in C2's handoff (C1 may not edit it). Cursor: advance to the max `last_edited_time` seen, never past it.
3. **Webhook (E):** call `route_notion_webhook` in a **system** transaction as `rf_api` after verifying the signature, then enqueue `sync_page` (priority `webhook`) in each returned tenant's own transaction. Only `active` connectors are routed.
4. **Maintenance job (A/C2):** run `purge_tombstones` as `rf_worker` in a loop until it returns fewer than `limit`. It uses `SKIP LOCKED` and never deletes a document that a sync un-tombstones at the same moment.
5. **Grants follow ADR-0013 exactly:** `take_tokens`, `penalize_tokens` and `purge_tombstones` go to `rf_worker`, `route_notion_webhook` to `rf_api`. If E validates connects (`GET /users/me`) through `NotionClient` with the DB limiter, `rf_api` needs EXECUTE on `take_tokens` and `penalize_tokens`, which needs an ADR-0013 amendment. Alternatively, E can use a no-op limiter for the two connect-time calls.
6. **Observability (Phase 2):** DESIGN names the metric `rf.notion.unsupported_block{type}`. No metrics library exists yet, so the counts go into document metadata and a `notion.unsupported_blocks` log event. Wire a counter when OTel metrics land.
7. **No new dependencies.** The client uses plain `httpx`; the `notion-client` entry in the `ingest` extra is unused by C1 and can be dropped.
8. **DESIGN 6.2 drift:** it lists `connector_rate(connector_id ...)`, but 0001 and ADR-0007 use `notion_rate(integration_key = sha256(token))`. The code follows 0001 and ADR-0007. Please fix the doc line.

## Notes and gotchas
- `run_sql` goes through the psycopg paramstyle, so the slot SQL must contain no `%` character, not even in comments.
- The bucket is a debt bucket. A caller always takes its tokens; the function returns the wait in ms, and the adapter sleeps that long. Capacity is 3 and the rate is 3/s; at most 1800 tokens per call (the adapter splits larger drains).
- A 429 Retry-After goes through `rf.penalize_tokens`, which CLAMPS the balance to at most `-ceil(retry_after * 3)` instead of adding debt. So N workers hitting the same 429 window cause one wait, not N, and a long Retry-After (above `max_retry_after_s`, 60 s) is applied to every worker. The reporting coroutine re-queues its job, and every other worker's next `acquire` sees a wait above `max_wait_s` and raises `UpstreamRateLimited` too, so nobody sleeps on a job slot (the token that `acquire` took is wasted: ~333 ms of extra debt per give-up, cheaper than a peek round trip on every request). The penalty is capped at 1800 tokens (10 minutes); the job still gets the full Retry-After via `UpstreamRateLimited.retry_after_s`. A limiter that only implements the frozen `RateLimiter` port falls back to `acquire(tokens_for_delay(...))` for short delays (and cannot apply long ones). Proposed port change, not made: add an optional `penalize(key, seconds)` to `RateLimiter`.
- Media blocks keep only the caption and file name, never the signed S3 URL. Without a `name`, the file name is the URL PATH basename (query string dropped, so no signature), only if it has an extension (`youtube.com/watch` yields nothing).
- Synced originals answering 403 (`restricted_resource`) or 404 are "unavailable" (`metadata.unavailable_synced_blocks`), not a fetch failure; 5xx/401 still fail the fetch.
- **Link safety is owned by E's OutputSanitizer.** The normalizer only does hygiene: http(s)-only hrefs, whitespace/`()<>` percent-encoded in hrefs, `[`/`]` escaped in link text. Plain text is NOT Markdown-escaped (it would mangle `[x]`), so indexed text can still literally contain `[x](javascript:...)`.
- The test helper is imported as `from module_c1.c1_support import ...` (a namespace package; no `__init__.py`, no conftest in module_c1). This is the name both pytest (packages/core/tests is on sys.path through the root conftest) and `make typecheck` (mypy_path includes packages/core/tests, explicit_package_bases) resolve. **Integrator note:** modules A, D1 and E1 still import their helpers as top-level `a_support` / `d1_fakes` / `e1_support`, which makes `mypy packages/core/tests` fail with `import-not-found`; the same `module_x.helper` import fixes it.
