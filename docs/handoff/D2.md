## Contract for module D1 (agent runner)
- **Graph config:** `configurable = {"thread_id": str(conversation_id), "rf_tenant_id": <UUID>, "rf_run_id": <UUID>}`, which is exactly what `fenced_config()` builds. Pass UUID objects, not strings: LangGraph copies str/int configurable values into checkpoint metadata.
  - Readers (`aget_state`, history) omit `rf_run_id`.
  - A missing `rf_tenant_id` raises `ValueError`. That's fail closed.
  - D1 can't import adapters (import-linter), so either duplicate the two key names or have bootstrap hand D1 a config factory. Proposal: move `CONFIG_TENANT_ID` / `CONFIG_RUN_ID` into `domain` (frozen; needs approval).
- **`LeaseLost`:** fenced writes raise `domain.errors.LeaseLost`. Under the default `durability="async"`, a failed background write surfaces at the end of the step. Use `durability="sync"` if the node after a lost lease must never start.
- **Reads:** a read without `checkpoint_id` resolves `conversations.head_checkpoint_id` for the root namespace. With no head, it returns `None` (a new conversation).
- **Disabled saver operations:** `adelete_thread`, `adelete_for_runs`, `acopy_thread` and `aprune` raise `NotImplementedError`. To delete a conversation, delete its `rf.conversations` row; the trigger cleans up.
- **`acquire`:** raises `NotFound` when the conversation isn't visible in the tenant, rather than 409. That avoids an existence oracle and means "404 unknown conversation". It raises `TurnInProgress` only when another live run holds the lease.
- **`lock_pending(tx, run_id)`:** returns **all** of the run's approvals, of any status, row-locked. The caller proceeds only if they're all `pending`.
- **`expire_pending`:** writes one `audit_log` row per expired approval (`actor='agent'`, `action='approval.expired'`, identifiers only, never tool args).
- **Store namespaces:** must start with `(str(tenant_id), str(user_id), ...)`. Isolation there is application-level (ADR-0013). The user-delete trigger relies on that prefix.
- **SQLSTATE `RFL01`:** shared with module A's job `assert_lease`, so both mean "lease lost".
- **Lease functions need the tenant:** `rf.assert_run_lease` / `rf.heartbeat_run` reject when `app.tenant_id` is unset. The saver and `SqlConversationRuns` always set it; any new caller must too.
- **`OllamaChatModel` errors:**
  - Every provider failure is a `ChatModelError` (status 502), including transport failures (Ollama down, dropped connection, timeout). Messages are fixed strings with no URL. `UpstreamRateLimited` stays separate for 429/503.
  - `OutputTruncated(ChatModelError)` replaces the final `UsageReport` when Ollama reports `done_reason == "length"` (num_ctx exhausted). Text already streamed is a cut-off answer: mark it partial/failed, and record `exc.usage` for metering. `complete_json` raises it too.
- **Tool results and Ollama:** Ollama has no tool-call ids; it matches a tool result to a call by `tool_name` and position. Our uuid ids never leave the process. When the model makes two parallel calls to the same tool, D1 must append the `Role.tool` messages in the same order as the calls in the assistant message. The adapter preserves message order exactly (tested).

## Known gaps / proposed follow-ups
- `FencedPostgresSaver.alist` now streams from inside its read transaction instead of buffering. A consumer holds one pooled connection (LangGraph pool, max 5) until it finishes or closes the iterator. Close abandoned listings with `aclose()` / `contextlib.aclosing` rather than relying on GC.
- `complete_json` constrains output with Ollama's `format` (JSON schema) but doesn't validate against the schema. No `jsonschema` dependency; repair/validation is the caller's policy, per the port.
- `ChatModelError` lives in the adapter. Proposal: a domain `UpstreamError(RagforgeError)` with status 502, so E can map it without the adapter. Mapping by `.status` already works.
- Subgraph namespaces (`checkpoint_ns != ""`) are fenced, but their reads use the library's latest-by-id within the visible thread. Only the root namespace has a head column.
- The `think` capability fallback keys on HTTP 400 with "think" in the error text. That's Ollama's current wording; it's covered by a test with a recorded message.
