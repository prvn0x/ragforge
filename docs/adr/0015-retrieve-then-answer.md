## Current state (read this first)
The guarantee in one paragraph: an answer is `verified` only if the verifier calls it supported AND its **residue is empty**. The residue is every substantive unit of the CommonMark-parsed answer that is not covered by a valid model label, not covered by a ground-checked inferred citation, and not an allowlisted phrase. Every unit attribution rejected (uncited, or with unbacked code) stays residue, whatever the text-keyed residue says. **Measured residual: identifier typos (Phase 2c).** The ground check reads meaning, and twice passed `processing.guarantee=exactly_one_v2` for a page saying `exactly_once_v2` (dev runs C4, C5; the model repeats this typo). An identifier-exactness rule was added and then **reverted**: its blind review found five P1s. It checked per unit, after segmentation cut dotted names. It used substring matching. It read raw Markdown, so escaped underscores hid names. Its `=` sentence-end change reopened the sentence-merge class. It also broke tool-cited replies. Done properly, it extracts identifiers per paragraph from the rendered text, matches them on token boundaries against the cited pages' identifier sets, applies to `S` labels only, and is property-tested with one-character mutations. That is a planned follow-up, not a shipped guarantee. **Code is covered only as a whole fenced block or a whole inline code span of a cited source, exactly, with ONE narrow exception (owner decision 2026-10-18, FLAG):** an inline code span of a model-labelled sentence whose content is a single ASCII identifier (`[A-Za-z_][A-Za-z0-9_]*(\.[A-Za-z_][A-Za-z0-9_]*)*(\(\))?`) that also LOOKS like one (has `_` or `.`, ends in `()`, or has a camel hump) is backed when it is a whole token of a code element (fenced/indented block or inline span) of the SHOWN chunk of an `S` label the sentence cites. A simple name may match any segment of a dotted source name. A dotted name must equal a whole maximal one. `name()` matches `name(` with any arguments. The match is case-sensitive and does no normalisation: any non-ASCII character, a neighbouring character that continues the token (`[A-Za-z0-9_$-/\]` or non-ASCII), or bidi/RTL/blank glyphs in the source code mean no match. It never applies to inferred citations, `T` labels, prose of the page, uncited pages, multi-token spans, or spans with `=`, arguments or spaces; those keep the whole-element rule. `joined_code`, `_ends_inside` and every other fail-closed rule run first. **Limits:** the rule backs the NAME only. What the sentence says about it ("`x()` deletes the database") is verifier-dependent like any prose (section 4.1). A name may match a same-named identifier in an unrelated part of the cited chunk's code, including one that appears only in a comment or a string literal of it (`// never call dropAllTables()` backs the name `dropAllTables()`; whether the sentence about it is right is the verifier's). Every flagged claim also carries a reason: `inexact_code` (muted on clients) only when the labelled unit's code is unbacked but each of its code elements is a contiguous, unaltered excerpt of ONE code element of a cited `S` source (same tokens, same punctuation, same order, gaps where the source has whitespace; it starts and ends at a whitespace boundary of the source and does not stop on an open argument such as `rm -rf /` or `--topic`), every identifier-shaped name in it is a whole token there, and the verifier's objections could all be placed in the answer. Everything else is `not_found`: typos, changed values (even when the new value appears elsewhere in the page's code), reordered or truncated commands, dropped interior lines, verifier claims, residue and uncited units; not_found wins by positional overlap with a verifier claim. Reasons never change the status: an `inexact_code` claim still makes the answer `partial`. Limit: an excerpt that ends at a whitespace boundary can still drop meaning that follows it (a trailing `--force` left off), and a LEADING or TRAILING line of the source block can be missing (a guard such as `if [ "$ENV" != dev ]; then exit 1; fi`, or a warning comment); the muted flag ("code shortened from your notes, check it") still marks it as not verified. A Phase 2b exception let a backticked word quote the page's plain prose; review rounds 2–9 found a P1 in it eight times, so the owner removed it after round 9 (2026-10-18). The cost is verified%; correctness is unaffected. A code span in the answer must also stand alone in what the reader sees (`joined_code`), and a span whose text ends in a terminator (closers, emphasis or invisible characters may follow it) ends the sentence. Bidi controls (raw or as HTML entities), any right-to-left character (R/AL/AN) and blank-rendering glyphs (braille blank, Hangul fillers) make the whole answer residue. Look-alike terminators (Unicode `Po`, a dot-, question- or exclamation-named symbol or mark, or a non-cased character stuck to an ASCII token) end a sentence before a visible space. Anything the checker can't read faithfully is opaque, and so residue. The accepted residuals (verifier-dependent: recombined source words, antonyms, polarity pictographs) are in section 4.1. The prompt (`answer@11`, which also keeps a label off the closing fence line; ADR-0016 for its section shape) asks for plain text for names from prose, so the model backticks less. **Dotted names (owner report 2026-10-19, DOT).**
- *What a dot does.* A single ASCII "." that is followed by `[a-z0-9_]` (never a capital) is not a sentence end when the maximal `[A-Za-z0-9_.]` run around it (leading/trailing dots stripped) is a dotted name found verbatim in what the reader sees of the SHOWN `S` sources (`coverage.dotted_names`: the parsed Markdown view, code spans and code blocks included; case-sensitive, never from `T` tool results). `segment`, `residue`, `visible_runs`, `attribute` and `settle` take the set (`names=`), and the interview path passes it. The chat path (`nodes._names`: shown `S` sources only, the same set for every reader of one draft) and the strict citation check (`check_citations`) pass it too; `test_ag_dot_chat_path.py` runs both live sentences through the chat path to `verified`. Without it, the last dot of "max.in.flight.requests.per.connection to 1 [S2]." and of "/actuator/loggers/{logger.name} with ... [S1]." cut the sentence, and the backed first fragment was flagged.
- *Why source-backed.* A shape rule ("two or more dots between identifier characters is a token") was rejected in design review: it merges "Kafka is fast.and.it never loses data", which hides a sentence end exactly as "node.js.it" once did.
- *What it never does.* It only removes cuts at interior dots of runs the page shows as one token. A dot followed by whitespace, a closer, an emphasis mark, a code span or the end is never exempt. A dot followed by a capital is never exempt, in any run ("fast.It", "2.8.It", "U.S.The", "kafka.streams.It", and so "java.util.List" keeps its old cut before "List"), even when a page holds it: a reader sees a period then a capital as a sentence end, and a missing space is a common typo in pasted notes. Dot runs, look-alike dots, `_dot_like`, `_foreign_tail`, bidi, RTL and blank-glyph rules stay ahead of it.
- *How it is held.* Hypothesis tests show the cuts with names equal the cuts without names minus exactly those dots, and that no dot followed by whitespace or by a capital is ever merged, even when every dotted run of the answer is backed. With no names the segmentation is unchanged (differential check on 35k texts).
- *Sources.* Sources are cut with the same names, so a page's own lowercase no-space run ("not durable.it is fast") is one source sentence for the negation and number evidence, as the reader sees that page. The inferred citation is still ground-checked.
- *Residual.* A source that holds a lowercase no-space typo ("durable.it", "fast.and.it") verbatim exempts that run in the answer too. This is accepted: the reader sees neither a space nor a capital there, so it is not two sentences to a reader. A capitalised typo ("fast.It", "2.8.It") is never exempt.


## Context
Phase 2b measured the answer path on the private eval set (dev split, n = 15: 13 answerable, 2 must-abstain; llama3.2:3b on an M1 Pro; `docs/NEXT.md`, "Phase 2b handoff"):

| arm | correct | content | draft | cited | abstain ok | p50 | p95 | ttft | tool turns |
|---|---|---|---|---|---|---|---|---|---|
| A0: tools bound on every turn (old default) | 15% | 54% | 77% | 15% | 2/2 | 22.0 s | 52.8 s | 8.5 s | 13 |
| A1: `max_tool_rounds=0` (retrieve → answer) | **46%** | 46% | 69% | 46% | 2/2 | 12.7 s | 22.0 s | 3.2 s | 0 |

Two findings drive this ADR:
1. **Tools on the answer path hurt a small model a lot.** It called tools it didn't need and passed them garbage: its own JSON schema as an argument, or `"[S1]"` as a `document_id`. Every bad call cost a round trip, and many turns ended in an abstain. Removing tools tripled the correct rate and halved p50.
2. **The dominant remaining failure is provenance, not knowledge.** Drafts had the right facts and **zero `[S<n>]` labels**. With no citation the answer has no provenance, the strict regeneration also came back uncited, and the turn abstained. The A0 Cassandra and livelock drafts were correct and were thrown away.

The eval is small (n = 15), so the numbers set a direction, not an effect size. **Latency** is a clear effect: every turn got faster and p95 fell from 52.8 s to 22.0 s. **Correctness** is direction only: paired on the 13 answerable questions, 5 were correct only without tools and 1 only with them (exact McNemar p ≈ 0.22), and each rate has a wide 95% Wilson interval (46% is 6/13, about 23–71%). The decision rests on the latency effect, the observed tool misuse (finding 1) and the direction of the correctness change, not on a significant correctness gain. *(Corrected 2026-10-17 after the Phase 2b review: this sentence previously said the gap was "far beyond what one or two flipped questions could explain", which overstated the evidence. `ragforge-eval compare` now prints these intervals and the paired test.)*

Tools are still needed for things the user explicitly asks the system to *do*: remove a page from the index, remember or forget a fact, and report sources or sync status.

## Options
**A. Tool binding**
1. *Tools on every turn (status quo).* Measured worst on correctness and latency.
2. *No tools ever.* Simplest option, but it loses remember/forget/remove, which are product features (DESIGN section 8, memory and HITL).
3. *An LLM intent classifier per turn.* Adds a model call to every turn, which breaks the latency budget (p95 target < 10 s). It is also a small model's judgment on exactly the decision we want to be reliable.
4. *Tools only on the second pass (answer first, then let the model ask for tools).* The model still sees tool specs on every turn, and an extra pass is needed whenever it wants one.
5. **Deterministic intent detection on the user's raw message, binding only the matched action's tools (chosen).**

**B. Citations from a small model**
1. *A stricter prompt only.* Necessary, but the A0/A1 strict regenerations show it isn't sufficient on its own.
2. *A bigger model.* Being measured separately (arms A2/A3). It doesn't help users on the 16 GB machine today.
3. *Embedding-similarity attribution.* One embed call per sentence on the critical path. It's also harder to reason about in a test.
4. **Lenient parsing, then deterministic lexical attribution, with every inferred citation gated by the existing ground check (chosen).**

## Decision
### 1. The answer path binds no tools
`AgentSettings.tool_mode = ToolMode.actions` (default). On a question, `generate` binds **no** tools, and its system prompt contains no tool rules (`answer@11` renders `$actions` empty). `ToolMode.always` reproduces the old behaviour; it is kept only as an evaluation override. `max_tool_rounds` stays the hard cap in both modes, and 0 disables tools entirely, including actions.

### 2. Explicit actions reach only their tool
`agent/actions.py::detect` classifies the user's **raw** message once per turn, in `_turn_input`. The result is checkpointed in `state.action`. It can never come from retrieved text or model output, and a resume binds exactly what the turn started with.

| ask | commands | narrow phrasings (anchored at the start of the message) | tools bound |
|---|---|---|---|
| remember | `/remember <words>` | "remember that…", "please remember:", "keep in mind that…", "don't forget that…"; with a "?" only as "can/could/would/will you remember that…?" | `remember_fact` |
| forget | `/forget <fact id>` | "forget … fact …" (the word *fact* in the same clause: "forget the fact that…", "forget about the Postgres fact") or "forget [fact:…]" | `forget_fact` (HITL) |
| remove page | `/remove <page>` | "remove/exclude/delete/drop/unindex `<quoted title>` or `<… page/note>` from my/the index" (or search, knowledge base) **ending the message**, "stop indexing `<… page>`" | `remove_from_index` (HITL) |
| sources | `/sources` | "what are my sources", "list my connectors", **ending the message** | `list_sources` |
| sync | `/sync` | "sync status" / "what is my sync status" **ending the message** (optionally "of my notes/sources/Notion"), "when did Notion / my notes / my sources last sync" | `sync_status` |

- **Destructive phrasings are the narrowest.** The owner's corpus is databases, Kafka and system design, where "delete a key from the index", "drop duplicate rows from the index" and "remove the leader from the ISR" are ordinary *questions*. A false positive on a destructive action is not free: it binds the destructive tool, switches the prompt to "perform an action", skips the weak-grade abstain and invites the model to propose de-indexing the user's most relevant page. So a destructive phrasing (forget, remove):
  - needs an explicit object: a quoted title, or words ending in page(s)/note(s) right before "from my/the index", and that phrase must end the message. "doc"/"document" are not accepted (review round 4): "delete stale documents from the search index" is an Elasticsearch question in this corpus, and "remove deleted notes from the index in Elasticsearch" names somebody else's index;
  - for forget, must name a fact: "forget what I said, explain Raft" and "forget about consistency, …" are conversational (review round 4);
  - is never inferred from a question: a message containing "?" never matches, and the "can you …" form is accepted only for non-destructive actions;
  - is otherwise left to the command. A short imperative such as "remove the handbook" or "remove it" is **not** detected (use `/remove`).

  The negative cases (B-tree, ISR, stopwords, page-table questions) are in `test_questions_are_not_actions`.
- **Remember is a write, so a question never binds it (review round 4).** "Remember that Redis is single threaded?" is a recall question; binding `remember_fact` there would let a small model store a fact the user never asked to keep (the quote gate passes, because the quote is a verbatim substring of the message), and that fact is injected into every later prompt. So the bare remember phrasing never matches a message containing "?"; only the explicit request form "can you remember that …?" and `/remember` do. Read-only phrasings (sources, sync) may still be questions.
- **A remember phrasing with a second request is a question (review round 5).** "keep in mind that Postgres uses MVCC, how does vacuum work" has no "?", yet its second clause asks something. As a remember turn it would be answered under `action_reply@1` from tool results only, so the question would silently never reach the notes. `detect` therefore treats a remember phrasing as a question when, after the matched phrase, a clause or sentence separator (`, ; : .`, a newline, a dash) is followed (optionally after "and/but/so/also/now/then") by an interrogative or request word (how, what, why, does, did, is, are, can, could, should, would, explain, describe, compare, tell me, show me, summarise, give me). Relative clauses ("…, which means …") and lists ("A, B and C") stay part of the fact. A false negative costs one turn answered as a question; `/remember …` always works.
- **Sources is anchored at the end (review round 4)** like sync: "show me my sources of truth for Kafka consumer lag" is a corpus question.
- **Sync is anchored to the user's own sources.** Non-destructive false positives are cheap but not free: the turn binds `sync_status`, answers under `action_reply@1` and is never page-attributed, so the notes are never consulted. "Sync status of replicas in Kafka" or "when did the follower last sync with the leader?" are replication questions about the corpus. So "sync status" must end the message (or name my notes/sources/Notion), and "last sync" needs Notion, "my notes" or "my sources" as its subject. These replication questions are in the negative test set.
- **A command word ends at whitespace, ":" or the end of the message (review round 5).** With a word boundary, a pasted path such as "/sources/foo is a dir" was the sources command and "/remove/tmp" a removal of "/tmp". Paths are now questions (`test_questions_are_not_actions`).
- **Fixed-argument commands are built by the server.** `/remember <words>` → `remember_fact(user_quote=<words>)`, `/forget <id>` → `forget_fact(fact_id=<id>)`, `/sources` → `list_sources()`, `/sync` → `sync_status()` (`actions.server_call`, minted once in `_turn_input` and checkpointed). The first generate step then makes **no model call**; the model only writes the reply. The documented path is therefore deterministic end to end, and an action turn costs one model call less. Server-built calls go through the same closed-schema validation, the `remember_fact` quote gate and the approval node as a model's call. `/remove <page>` is excluded on purpose: choosing which retrieved page the words name is the model's judgment, which a human then approves. A phrasing (not a command) still lets the model fill the arguments.
- **The reply step has its own prompt.** After the tool ran, the reply is generated with tools unbound under `action_reply@1`, which says the outcome is in the `<tool_result>` blocks, to cite them as `[T<n>]`, and to say exactly when an action failed or was rejected. The plain answer prompt would tell the model to answer only from `<source>` blocks or reply "Your notes don't cover this.", which is wrong after `/sync` or an approved removal. `actions@2` (the tool-calling step) no longer carries reply instructions.
- **An action reply is never attributed to a page.** Its sentences report a tool result; giving "The page was removed." whatever page shares its words would invent provenance. Uncited reply sentences are highlighted (`partial`), never inferred.
- **One round.** An action binds its tools for **one** generate step. The model then writes its reply with tools unbound, so a small model can't loop on the same call.
- **Registered but unbound tools are dropped.** If a model calls a registered tool that wasn't bound (e.g. `remove_from_index` on a remember turn), the call is dropped and never executed. An unknown tool name is still answered with an error, as before.
- **A server-built command retrieves nothing (review round 3).** `/sync`, `/sources`, `/forget <id>` and `/remember <words>` go from `load_memory` straight to `generate` (`graph.after_memory`): no page can change the call, and the reply is never page-attributed, so embedding and reranking the command text would only add latency and a meaningless `TurnSources`. This holds only when the call will actually be made: with `max_tool_rounds=0` the command is a question again and retrieves.
- **The action is the query.** For a command that retrieves (`/remove <page>`), the retrieval query is the command's argument (`/remove Kafka basics` searches "Kafka basics"), so `remove_from_index` is shown the page's `document_id`. An action turn never runs `contextualize`, on any turn of a conversation (`graph.after_memory`): an LLM rewrite of a follow-up would replace exactly the words that name the page, and would cost the call the action path promises to save.
- **Actions don't abstain on a weak grade.** An action turn always reaches `generate`. "Remember that I prefer Java" must not end with "not in your notes".
- **The safety properties don't depend on detection.**
  - Destructive tools still go through the approval node (`approvals:write`, which MCP keys never hold).
  - `remember_fact` stays quote-gated against the same raw message.
  - Arguments are still validated against closed schemas.

  A false positive therefore cannot lose data, but it does cost the user a confusing turn (above), which is why destructive phrasings are narrow. A false negative answers the message as a question, and the command form always works.

### 3. Small-model citation format, parsed leniently
`answer@11` (round 5 added "do not add greetings or offers of further help"; the coverage redesign added "a label covers only its own sentence"; Phase 2b made the yes/no rule apply only to yes/no questions (`@7`: its "Yes, the bridge…" example made Flash-Lite start every answer with "Yes,") and asked for a label on list lead-ins and backticks only for code copied from a code source (`@8`), and Phase 2c added the section shape and a firmer no-backticks-for-plain-text rule (`@9`/`@10`, ADR-0016)) and `answer_strict@4` are short and concrete. Each has one citation instruction and one example, on a neutral topic (a bridge) so the model can't lift example "facts" into an answer about the user's own subjects. `citations.normalize_citations` rewrites citation-shaped markers to canonical `[S<n>]` before the deterministic check:
- **Forms it accepts:**
  - `[1]`, `[1, 2]`, `[1][2]`, at a clause end only (before `. ! ? , ; :`, another marker, or the end of the line);
  - `(S1)`, `(S1, S2)`, `(S1 and S3)` at a clause end only; `(source 3)` anywhere (normalised in place: the reader sees the label where it is, so this moves no claim);
  - `[s1; s2]`, `[S 2]`, `[Source 1]`, `[Sources 1, 3]`, `[source: S2]`, `[S1, 7]`;
  - "Source: S1" (a bare label only after a "Source:" cue that starts a line or follows a sentence end, **and** only when it ends the line).
- **Text it never touches:**
  - "Amazon S3", "see S3", "cf. S3", "(see S3)", "Amazon Simple Storage Service (S3) is …", "the data source S3 holds …": S3 is everywhere in HLD notes, so there is no "see"/"cf." cue at all;
  - `arr[1]`, "[2024]" (bare numbers are capped at two digits);
  - a bare-number bracket mid-clause: "Use list [1, 2] in Python." (review round 3);
  - Markdown links `[1](url)`, `[S3 docs](url)`;
  - `(S3)` alone mid-sentence and `(S3, EC2 and Lambda)` (AWS product names);
  - a single `(S<n>)` at a clause end that closes a product name (review round 5): right after the same token ("S3 (S3)."), after a Capitalised run naming a vendor ("Amazon …", "AWS …"), or after a Capitalised run with at least n words starting with the label's letter, i.e. an acronym definition ("Simple Storage Service (S3).");
  - list markers `(1)`;
  - inline code and fenced code.
- **Accepted risk (review round 5):** a product named in lower case before a clause-end parenthesis ("stored in object storage (S3).") is still read as a citation. It is rejected if S3 was not shown; if it was, the verifier checks the pairing like any model label.
- **Accepted risk:** a bracketed small number at a clause end ("... in Python [3].") is read as a citation, because `[1]` is the form small models write most. If that label wasn't shown it is rejected like any fabricated label; if it was, the reader sees a model citation the model arguably did not mean, and the verifier checks that pairing like any other. It is bounded to `[n]` with n ≤ 99 **at a clause end**: mid-clause (`list [1, 2] in Python`) the bracket stays prose, and its sentence is attributed or highlighted like any uncited one. Marking normalised bare numbers as inferred was rejected: `[1]` at a clause end is the model's own citation in the only syntax it reliably writes, and relabelling it would hide that the model did cite.
- **Ranges are expanded, then checked.** `[S1-S3]`, `[S1-2]`, `[S2 to S3]` and `[Sources 1-3]` become `[S1, S2, S3]`-style lists when they span at most 8 labels, so `[S2-S9]` with two sources shown is rejected label by label. A descending or wider range is left as written and rejected as a stray fragment (below).
- **One definition of "carries a citation" (review round 2).** A *citation-shaped fragment* is a bracket whose content is only labels, numbers, separators and the words and/to/through, with at least one `S<n>`/`T<n>`, or a parenthesis of that shape holding **two** labels and a separator. Any such fragment left after normalisation that isn't a canonical marker (`[S2, S10000]`, `[1, S2]`, `[S3-S1]`, `(S1-S3)` mid-sentence) is an **invalid label**: the sentence is offending (rule 1). Attribution skips a unit only when it carries a canonical label (`Unit.labels` of `coverage.segment`), the same units `check_citations` iterates. Before this, a malformed label was "cited" for attribution and "no label" for the check, so a drifted number behind `[S2-S9]` reached `verified` and the reader saw a label naming an unshown source.
- **Normalisation never decides validity.** A lenient marker naming a label that wasn't shown becomes a canonical invalid label (`[7]` → `[S7]`), and `check_citations` rejects it exactly like a fabricated `[S9]`: the sentence is offending, then one strict regeneration, then abstain. A hypothesis property test checks that no text, however written, yields an accepted label outside the shown set, **and** that every sentence holding a citation-shaped bracket (by the test's own definition, independent of the implementation's) is either validly cited or offending.
- **Plain visible text only, by the guarantee's own definition.** Normalisation rewrites only `structure.Structure.label_spans`, the plain text of the CommonMark parse (section 4): never code at any depth (a fenced or indented block, also inside a quote or list item, or an inline span of any backtick count), a link's text or destination, an autolink, strikethrough or HTML. Stray fragments are looked for in the text the reader sees (`coverage.visible_runs`). `check_citations` runs on `coverage.segment` (section 5), so there is one definition of a unit, of code and of where a label is.
- **The client gets the normalised text.** If normalisation changed a streamed draft, `finalize` sends it once as `TurnReplace`, so the text the client holds is the text that unsupported claims are matched against.

### 4. The verification guarantee: coverage, not claim detection
**The guarantee.** An answer may be `verified` only if its **residue** is empty. The residue is the answer text minus:
- **(a) model coverage:** the spans a valid model citation covers. A label covers **only** the sentence or clause it terminates: the text from the previous boundary (sentence end, line break, cell, HTML or previous label) up to and including the label, plus any punctuation or pictographs between it and the boundary. Text after the last label of a sentence, an em-dash or semicolon clause after a label, and a following lower-case "sentence" are **not** covered. A bare run of labels with no words before it cites the unit right before it **only where the reader sees the two together**:
  - in the same paragraph, heading or table cell, separated by nothing but whitespace, terminators, closing quotes and pipes, across at most one soft line break ("A works. [S2]", "claim.\n[S1]"; not across a hard break, HTML or anything that says something, such as an emoji), and never onto a unit that **is** HTML, tag-shaped text or a leading enumerator (parser rewrite, review round 2: "partitions.<!-- NASA built Kafka in 1850 --> [S1]" let the label cover the comment, which an HTML-aware renderer hides, so the reader saw it citing the sentence before; "… [S1]. 3) [S1]" let a label cover a bare enumerator that may be the answer);
  - starting the paragraph on the line right after a code block, in the same container ("```…```" then "[S3]");
  - alone at the start of the next cell of the same table row (a sources column).

  Anywhere else it is an **orphan** and covers nothing: after a blank line, a rule, a quote or list marker, an emoji, or right after HTML, tag-shaped text or a leading enumerator. Its labels are still checked (rule 1);
- **(b) inferred coverage:** the units whose inferred citation **passed the ground check** (section 4.2);
- **(c) a closed allowlist** of non-claim text (`coverage.allowed`), matched against the **whole** unit's words (cleaned, casefolded; punctuation and emoji ignored, every word counts):
  - closing pleasantries ("Let me know if you have other questions.", "I hope this helps.", "Happy to help.") and three lead-ins on a sentence or line of their own ("Here is what I found:", "Here is a summary:", "Here is what your notes say:");
  - whole-sentence refusals: "(your|my|the) (notes|sources) (don't|do not) cover (this|that|it) [question]" and "I couldn't find this in your notes". A refusal that adds **any** word is not allowlisted: "No, it doesn't cover that.", "Your notes don't cover this; no.", "… cover this, but yes.";
  - markdown structure, which the parser consumes and so never reaches a unit: quote, heading, bullet and table-delimiter markers, fences of a code block, the numerals of an **actual numbered list** (one that starts at 1 or continues the count of the list before it) whose item **says something besides citation labels** (parser rewrite, review round 3: "1. A [S1].\n\nHere is what I found:\n\n2." showed a lone "2." and "1)\n2)\n3)" rendered a count, both `verified`; an empty item's numeral, or that of an item holding only labels or a pictograph, is now residue), HTML that the **parser** recognised (an inline HTML token or an HTML block) and that is nothing but **bare** line-break and block tags (`<br>`, `<br />`, `<p>`, `</td>`…: the tag name and nothing else, `structure.bare_html`; attribute text such as `<p NASA built Kafka in 1850>` is text the reader sees, because the sanitizer escapes raw HTML, and "< br/ >" is not HTML to the parser, so its text is text), and text made only of characters that **state nothing** (below). A numeral outside a numbered list is text: "3. Kafka …", "100. …", "> 42) …" keep the number, which may be the answer to "how many". A task box ("[ ]", "[x]") is text too (no rule exempts it since the parser rewrite's first review; a labelled or inferred item covers it with its sentence, and "x" alone is no content word).

**Where the structure comes from: a real CommonMark parse (review of the redesign, round 4).** Until round 3 the units were found by regexes for fence lines, indented lines, backtick runs, list markers and table rows: a second Markdown grammar next to the reader's renderer, and every disagreement was a bypass. The review found indented code with a label read as prose, fences and indented code nested in blockquotes and list items read as prose, inline spans cut in two by ".", ";" or a line break, double-backtick spans, and labels counted inside link destinations, autolinks and strikethrough. Now `agent/structure.py` builds **one structural map** from markdown-it-py (CommonMark preset with raw HTML recognised, GFM tables and strikethrough, linkify when `linkify-it-py` is installed with fuzzy links off; `text_join` off so escapes and entities stay separate tokens):
- **every code element at any nesting depth:** fenced and indented blocks (`fence`/`code_block`, inside blockquotes and list items too) and every inline span (`code_inline`, any backtick count, across line breaks), each with the parser's own content;
- **links, autolinks, linkified URLs, images, inline and block HTML, strikethrough, soft and hard line breaks, escapes and entities**, and the **visible text runs**;
- **source positions:** block tokens carry line ranges; each inline token's content is aligned back onto its source lines (container markers and whitespace before it, whitespace or a heading's closing hashes after it; a table cell's content from its row, `\|` read as `|`). "Whitespace" is the Unicode set `str.strip` removes, because markdown-it strips paragraph, heading and cell content with `str.strip()` (parser rewrite, review round 3: an ASCII-only rule made a paragraph, heading or table row ending in NBSP, U+202F, U+2003 or U+3000 opaque, so a cited answer was `unsupported`; fail closed, but a recall loss on French typography and copy-pasted text), and each child token is aligned onto that content **in order, every step checked**: a text token must equal the source it spans, a link's extent is recomputed by markdown-it-py's own link rule, a code span ends at the first backtick run of its opener's length. A part whose alignment does not check out (for example a tab the block parser expanded inside a list item) is **opaque**: fail closed, never guessed;
- **accounting:** every source character is inside a part (an inline block, a code or HTML block, an opaque block) or is structure that states nothing. An unclaimed run that says something becomes an **opaque unit**: a reference definition (CommonMark renders nothing, the sanitizer shows it literally, and it turns a later "[S1]" into a link), a cell beyond the header's width (the table rule drops it), the numeral of a list that does not start at 1, and the numeral of an empty item. A code or HTML block starts at its fence or first content line, not at the start of its first line, so a list numeral before it is accounted separately (found by this round's own stress run: "3. ```…```" let the numeral ride on a verbatim-attributed block).

**What is not the parser's.** The fence, indentation, backtick, list, task-box, table-row, strikethrough and bare-tag regexes of `coverage.py`, `labels.mask_hidden`/`inline_code_spans` and attribution's `_source_blocks`/`_INLINE_CODE`/`_PROMPT` are deleted; the check, strict mode, normalisation, attribution's reading of source pages and the residue all read the same cached parse (`structure.structure`, `coverage.segment`, `coverage.visible_runs`). What is left outside the parse tree is listed here, exactly; each item can only **add** a cut, **reject** a label or make a part **opaque**, never make text state nothing or cover it:
- `structure._PREFIX`, `_SUFFIX`, `_BREAK`: they *locate* the parser's own content on its source lines (container markers before it, trailing blanks or closing hashes after it, a line break between). Every location is then checked (text must equal its source), and a mismatch makes the part opaque;
- `coverage._ENUMERATOR`: a leading "(7)", "7)", "(a)", "b." that is not a list numeral is cut off as its own unit (the parser reads it as text; it may be the answer), and a bare label run right after it is an orphan;
- `coverage._TAG_LIKE`: text shaped like a tag that the parser did **not** take as HTML ("<p NASA built Kafka in 1850>", invalid attribute name) is a boundary on both sides, holds no label, and a bare label run right after it is an orphan, because another renderer may read it as a tag. It never states nothing;
- an unterminated `<!--` (text to the parser, a comment to an HTML-aware renderer): no label after it;
- `coverage._url_shaped`: no label inside a word a renderer may linkify (without `linkify-it-py` the parser reads a bare URL as text);
- the terminator, clause-end and identifier-dot rules (`coverage.sentence_ends`), which are not Markdown at all.

**Units** (`coverage.segment`) are computed per part:
- an inline part (paragraph, heading, table cell) is segmented **only over its visible text**: plain text, escapes and entities as the characters the reader sees; a code span, an autolink, a linkified URL and an image as one atomic character (never cut inside); a line break as a newline. The units partition the part's source, so a link's destination, emphasis markers and container markers on continuation lines belong to the unit around them (hidden text inside a unit is residue unless the unit is covered);
- a code block (fenced or indented, at any depth) is **one** unit; an HTML block and an opaque block are one **opaque** unit each: never inferred, never allowlisted, and no label inside them counts.

**Boundaries** inside visible text (an extra cut only adds residue, so every rule is a superset):
- **sentence ends** (`coverage.sentence_ends`): **every** Unicode `Sentence_Terminal` character (Unicode 15.0 PropList, united with every punctuation character named FULL STOP / QUESTION MARK / EXCLAMATION MARK / DANDA / ELLIPSIS / INTERROBANG, the dot leaders, the Greek question mark and the Tibetan shads), **whatever follows it**: whitespace, nothing, a zero-width space, a quote, an upper- or lower-case letter. Closing quotes and brackets right after the terminator stay with the sentence it ends. The **only** exemptions are a single "." inside a token and the final dot of "e.g."/"i.e.". A token is digit.digit ("3.5"), or lower.lower **in an identifier**: the word after the dot is on a closed list of file extensions, TLDs and abbreviation letters ("node.js", "postgresql.conf", "example.com", "e.g"), or the word after the dot is followed by ".", "/", "_", "(" or a backtick ("os.path.join("). Only what follows the dot counts (round 2: a chain before it let "on node.js.it runs on port 9999 [S1]." cover two sentences). A test rescans `unicodedata` and fails if a punctuation character named like a sentence end is missing;
- **clause ends:** a semicolon in any script (`;`, `；`, `؛`, `⁏`, the Greek ano teleia, small and vertical forms);
- **cells and lines:** every table cell the parser finds is its own part; every "|" in visible text (escaped or not) ends a unit; every soft or hard line break and every Unicode line separator is a boundary;
- **URLs:** an autolink or linkified URL is atomic, but one whose text ends with a terminator or a closer ends a sentence right after it (found by this round's stress run: linkify swallowed a final "…" into the URL, and the sentence end it hid let one label cover the sentence before it);
- **HTML:** both sides of parsed inline HTML (including comments), and of text shaped like a tag that the parser did not take as HTML (`<p NASA built Kafka in 1850>` has an invalid attribute name, so CommonMark reads it as text; some renderers would not). The HTML or tag-shaped chunk is its own unit, and no bare label run cites it (`coverage._Builder._has_html`); it states nothing only when the **parser** recognised it as HTML and it is nothing but bare break or block tags;
- **leading enumerators:** a "(7)", "7)", "(a)" or "b." at the start of a sentence that is not a list numeral is cut off as its own unit; nothing covers it (no bare label run cites it, and it has no lexical evidence), so it is always residue.

**Where a label counts** (`coverage._labels`). A canonical marker `[S1]`/`[T2]`/`[S1, S2]` is a label only when the reader sees it as one: in plain visible text whose source is **literally** the marker (`structure.Atom.eligible`), so **not** inside code at any depth, a link's text or destination or title, an autolink or linkified URL, strikethrough, HTML or a comment, an escape (`\[S1\]`) or an entity (`&#91;S1&#93;`); **and** not inside a URL-shaped word or glued to a linkified URL (a renderer may linkify it; without `linkify-it-py` this rule alone stands in for linkify), not after an unterminated `<!--` and not inside tag-shaped text.
- **Strikethrough is the parser's GFM reading** (parser rewrite, review round 1): markdown-it-py's `strikethrough_single_tilde` mode, i.e. GFM's delimiter-run rule: a run of one or two tildes opens only when left-flanking, closes only when right-flanking, opener and closer have the same length, and a run of three or more is text. "~[S1]~" and "~~[S1]~~" are struck; "The cluster has ~3 brokers [S1]. Autovacuum runs every ~60 seconds [S2]." is not (the old whole-paragraph heuristic, "any ~ before and any ~ after", rejected both labels and abstained a correct answer). The one place where markdown-it's default reading strikes what GFM does not is a run of three or more tildes ("~~~[S1]~~~"); a part holding such a run that the default reading strikes has **no** label at all (`structure._struck_in_pairs`; fail closed);
- **Every atom of a link is opaque** (`structure.Atom.opaque`, from "[" to the end of the destination and title), so a unit overlapping any part of a link gets no inferred citation and is never allowlisted. A link hides text the reader may still see: its destination (on hover; the sanitizer keeps it) and its title (parser rewrite, review round 3: only the "[" was opaque, so in `[! Kafka stores records in partitions](https://x.example "NASA built Kafka in 1850")` the "[!" unit stated nothing and the next unit held the link text, destination and title without the opaque atom, and was attributed to S1). A model label still covers a sentence with a link (accepted residual below);
- **A marker the reader sees but that does not count** (struck through, escaped, in a link's text, in a URL-shaped word, **inside an autolink or a linkified URL**) is an **invalid fragment** for the citation check (rule 1): it is never decoration riding on a covered sentence (`coverage.visible_runs`, `citations._stray_spans`). The text of every autolink and linkified URL is scanned like visible text (parser rewrite, round 1: "Kafka stores records in partitions http://x.com/[S1] ." reached `verified` with linkify, because the URL atom was never scanned, and `unsupported` without it). The result no longer depends on linkify: the attack lists and the property run with linkify on and off.

**Code is covered only whole and exact.** A code element is covered only as a **whole** fenced/indented block or a **whole** inline span of a source, exact up to trailing spaces and tabs, a uniform dedent and blank edge lines (`attribution.code_matches`). The dedent removes the longest string of spaces and tabs that **every** non-blank line starts with (`textwrap.dedent` semantics, `attribution._common_indent`), never a count of blank characters: counting took one space from one line and one tab from another, so " if ok:" / "\t    deploy()" / "\tcleanup()" moved `cleanup()` under the `if` and still matched the source block, labelled and inferred (parser rewrite, review round 2). Lines are split on "\n" **only** (markdown-it has already turned CR LF and CR into it): `str.splitlines` also splits on U+2028, U+2029, NEL, VT, FF and FS/GS/RS, so "cd /tmp/build<U+2028>rm -rf cache" (one line to the reader, another command when pasted) matched the two-line source block and reached `verified` labelled and inferred (parser rewrite, round 1); a trailing form feed or line separator is likewise part of the code. It is covered only when a fence's info string is empty or a language tag from a closed list (any other info string may carry prose, and some renderers show it). This holds for **both** kinds of coverage:
- **inferred:** a code block unit gets a candidate only from a shown source holding it whole and exact (and with at least 3 non-trivial tokens); a prose unit's inline spans must each be a whole code element of the source its prose is attributed to;
- **model-labelled:** a code block cited by a label line, or a sentence with inline spans that ends in labels, is covered only if one of the **cited** sources holds every one of its code elements whole and exact; otherwise the unit is residue, highlighted, and does not count as covered (`Attribution.code_unbacked`).

Source pages are parsed the same way: their code elements come from the parser, so a span inside a source's fenced block is part of that block, not an inline span of the page.

**What the tokenizer may read (round 4; parser rewrite, round 1).** Every word-level reading (the allowlist, lexical evidence, negation) first removes every format character (Cf: zero-width space and joiner, soft hyphen, BOM, tag characters) **and every other default-ignorable code point** (`coverage.DEFAULT_IGNORABLE`, a literal Unicode 15.0 `Default_Ignorable_Code_Point` table: the Hangul fillers, the combining grapheme joiner, variation selectors, Mongolian and Khmer invisibles), before and after NFKC (`coverage.clean`), so "n​ot" and "no<U+3164>t" read as the "not" the reader sees. Text holding a Hangul filler (a default-ignorable **letter**, which a tokenizer keeps inside a word and a renderer shows as a blank) is **opaque** as well. A word mixing two look-alike alphabets (Latin, Greek, Cyrillic, Armenian, Cherokee: "nοt" with a Greek omicron, "Kаfka" with a Cyrillic a) is **opaque** (`coverage.mixed_script`): its unit gets no inferred citation and is never allowlisted. Negation is detected on a skeleton that also drops accents, maps the common Greek/Cyrillic/Armenian look-alikes to Latin and reads every Latin small capital ("ɴᴏᴛ", generated from the Unicode names) as its letter, so an all-Greek "ΝΟΤ" and a small-capital "ɴᴏᴛ" are "not" (section 4.1). **Apostrophes** (parser rewrite, review round 3: "doesn´t", "doesn′t" and "doesn\`t" read as "doesn" + "t", so the negation was missed): every word-level reading first folds exactly these characters into "'" (`coverage.APOSTROPHES`, before NFKC, which would turn U+00B4 into a space and a combining mark): U+2019, U+2018, U+02BC, U+201B and U+FF07 (apostrophes and quotes), U+00B4, U+0060, U+FF40, U+02CA and U+02CB (acute and grave accents), U+2032, U+2035 and U+02B9 (primes), U+02BB, U+02BD and U+02C8 (modifier commas and the vertical line), U+A78C (saltillo), U+0384, U+1FFD and U+1FEF (Greek tonos, oxia, varia), U+055A (Armenian apostrophe) and U+05F3 (Hebrew geresh). Any **other** non-ASCII modifier letter, modifier symbol or punctuation character between two Latin letters ("doesnˮt") makes the text **opaque** (`coverage._joined`): no inferred citation, never allowlisted.

**"States nothing" is an allowlist too (review round 2, P1):** a unit is residue-bearing when it holds **any** character not positively known to state nothing (`structure.states_nothing`), or any code (a fence's info string counts). A character states nothing only if it is whitespace, punctuation (P\*), a separator (Z\*), a combining mark (M\*), a format character (Cf), one of the markdown symbols `| > ` ~ + < = ^`, or a pictograph (a symbol in the arrow, technical, geometric, dingbat and emoji blocks), **and** its NFKC form has no letter or digit, **and** its Unicode name does not say LETTER, DIGIT, NUMBER, NUMERAL, KEYCAP or FRACTION. Unassigned, private-use and control characters are substantive. Text the word tokenizer cannot see at all (braille, regional indicators, "€") makes a unit **opaque** (`coverage.opaque`).

Residue that holds a letter, digit or code means the answer is **never** `verified`: it is `partial` when some unit is covered (by a model label or a surviving inferred citation), otherwise `unsupported` (rules 2 and 4b below). Every residue unit is reported **verbatim** in `unsupported_claims`, so the client can highlight it.

**A pure refusal** (the whole answer is an allowlisted refusal, optionally with pleasantries; labels don't change that, so the strict prompt's "Your notes don't cover this [S1]." counts) makes no claim. Its status is **`unverified`**, and it is never badged `verified`. No ground check is spent on it (`graph.after_citations` routes only a `pending` draft to the verifier).

**Why coverage replaced claim detection.** Until review round 5, attribution decided which sentences were *claims*, using a denylist of word rules. Each of three review rounds found a new sentence the rules didn't see. A denylist fails **open** on every phrasing nobody thought of. Coverage inverts the burden: text is residue unless it is **positively** accounted for by (a), (b) or (c), so a new phrasing, script or format fails **closed** by construction. Round 4 applied the same inversion to structure: what is code, what is visible and where a label is comes from the parser the reader's renderer shares, and what that parse cannot classify is opaque.

**What it costs (recall, all fail closed and highlighted):**
- "Yes." / "No." as a sentence of its own is residue, even before a cited or inferred claim. `answer@11` asks the model, for a yes/no question, to put the yes/no in the cited sentence;
- headings and table cells are residue unless cited; each table cell is its own unit;
- every terminator cuts: "Yahoo!", "U.S.", "Node.JS", "3.x", URLs with "?" or "!" (outside a linkified URL) split a sentence, and the piece before the cut is residue unless attribution supports it; so is a list that does not start at 1 or continue the previous count, and a list lettered "a." / "b)";
- a label on its own after a blank line, a rule or a list marker is an orphan;
- a unit holding a symbol the tokenizer cannot see, a word mixing alphabets, a word joined by an unlisted apostrophe look-alike, **any link** (since the parser rewrite's third review; before, only a titled one) or an image gets no inferred citation; an empty numbered item's numeral is residue; a number word must sit next to the same neighbour in the source, like a digit; a unit absorbs at most 8 bare label runs;
- round 4: an **HTML block** is opaque, so an answer written as `<p>…</p>` is `unsupported` even when labelled (the sanitizer shows the tags literally anyway); a fence with an info string that is not a language tag is never covered; a canonical label inside a URL-shaped word, a link's text or strikethrough is not a label, and where the reader still sees it as text it fails rule 1 (regenerated, then abstained); a part the alignment cannot map (a tab the block parser expands mid-container) is opaque; without `linkify-it-py` (the production image today) a bare URL is text, so its dots and "?" cut;
- parser rewrite, round 1: a marker inside a URL fails rule 1 (it is shown, but names no source the reader can follow); a tag-shaped text the parser does not read as HTML ("< br/ >") is text; a part with a run of three or more tildes that markdown-it's default reading strikes holds no label;
- **lead-ins to code** ("To list topics, run:", then a fenced block) are residue unless they are cited or have lexical support of their own, so a how-to answer whose code is verbatim and labelled is still `partial` for its lead-in line. Not changed in this round on purpose: the reviewer's own fix says to measure first, and attaching a lead-in to its block's coverage would let prose ride on verbatim code (the follow-up measurement reports this bucket).

The follow-up measurement reports these buckets.

**Accepted residuals (not bypasses: the reader sees one sentence, and the verifier checks all of it).**
- A dot followed by a word that itself continues the token ("fifty.kafka.stores", "a.b(c") reads as one dotted identifier, like "os.path.join(", so it is not cut.
- A clause joined by a colon, comma, dash or parenthesis before a label ("NASA built Kafka: it stores records [S1].") is part of the sentence the label ends. A semicolon is not in this list: it cuts.
- A label alone on the next line of the same paragraph cites the last unit of the line before it, because Markdown renders them as one paragraph.
- A label covers its whole sentence, including the text of a link inside it and the link's destination, which the reader does not see as text: the model labelled the sentence, and the verifier is given all of it.
- **Pictographs state nothing** (`structure.states_nothing`): "Kafka has 3 brokers [S1]. 👍" is `verified`, although an emoji can carry meaning. This includes the **polarity and verdict glyphs** that negate or grade a claim right next to its label: "Kafka stores records in partitions [S1] ❌" (also ✗, 👎, 🚫) and "… [S1] ★★★☆" reach `verified` with an always-supported verifier, and so does an uncited "Kafka stores records in partitions ✗" through an inferred citation (lexical attribution ignores non-words). The verifier, which is given the whole answer, is the **only** backstop. Kept on purpose after the parser rewrite's third review: the alternative (an allowlist of decorative glyphs, every other pictograph residue) would make chat-style answers with ✅ bullets `partial` and give their uncited lines no inferred citation; it needs the eval-set measurement first. `test_accepted_residuals_are_pinned` pins these, so changing it is a deliberate decision.
- **Negation forms attribution does not read** (section 4.1): letters spaced out ("n o t"), Roman numerals ("III brokers" is not a number), negation in other languages (CJK "不", French "ne … pas"), antonyms and inverting prepositions ("outside partitions"). Each such unit can get an inferred citation and reach `verified` with an always-supported verifier; the verifier is the backstop (`test_accepted_residuals_are_pinned` pins the first three).
- **Renderer differences.** The map is markdown-it-py's reading (CommonMark + GFM tables + GFM strikethrough + linkify when installed). A client renderer with other extensions (footnotes, math, definition lists) could show structure the map reads as text. The known differences are handled fail-closed (markdown-it's default "~~" pairing of three-tilde runs, bare-URL autolinks, HTML-shaped text, unterminated comments); others are not claimed, and renderer parity of the actual clients needs live evidence (handoff).
- **Look-alike letters** are covered for words that mix alphabets (opaque), and, for negation only, through a hand table of the common Greek, Cyrillic and Armenian look-alikes plus every Latin small capital. An all-Cyrillic look-alike word is read as Cyrillic: it shares no evidence with a Latin source, so it can only cost recall; a look-alike outside the table and the small capitals (an IPA letter such as "ɑ", a mathematical letter NFKC does not fold) can hide a negation from attribution, which is then the verifier's to catch (negation only withholds candidates; it is not part of the guarantee).
- **Blank-looking characters that are not default-ignorable** (the braille pattern blank U+2800, a symbol) say something (`structure.states_nothing`) and make text opaque (`coverage.opaque`), so they cost recall; they never hide text from the residue.

In each case coverage guarantees a citation on every sentence, not that the citation is right.

#### 4.1 Attribution proposes; it no longer decides
`agent/attribution.py` is deterministic and CPU-only. For every unit that would otherwise be residue (substantive, not model-covered, not allowlisted), it proposes the best supporting **shown** source as a *candidate inferred citation*. Labels the model wasn't shown are never candidates. A unit it cannot support stays residue, so its weaknesses (paraphrase, short sentences, scripts it tokenises poorly) cost recall, never correctness.
- **Content token:** a word or number of the unit's **visible** text (code spans written out; a link's destination and other hidden source text are not evidence), cleaned (NFKC, no format characters), casefolded, not a stopword, with a light plural fold. There's no real stemmer, because one would manufacture overlap.
- **No candidate for an opaque unit:** an HTML or opaque block, a unit with text the tokenizer cannot see, a word mixing alphabets or joined by an unlisted apostrophe look-alike (`coverage.opaque`), or a unit overlapping text the reader may see but the tokenizer does not (any part of a link, whose destination and title are hidden; an image).
- **Lexical support** (prose units), all of these must hold:
  - at least 3 of the unit's distinct content tokens appear in the source's title, heading path or text, and they are at least 60% of the unit's distinct content tokens;
  - **numbers:** a number is one token with its sign, decimals and thousands separators ("-3", "3.5", "1,000"; a "-" right after a word is a hyphen). Number words are numbers, on both sides: zero to twenty, the tens, dozen, hundred, thousand, million, billion, and the ordinals first to twentieth. Roman numerals ("III") and other quantity words ("several", "a couple") are **not** read as numbers: such a unit only needs lexical support, and the verifier is the backstop. Every numeric token appears in the source, and for **every** occurrence its anchor in the unit (the content word right **after** it, or the one before it when nothing follows) is a neighbour of that number in the source, on either side, within one source sentence. This catches "3 partitions" against "3 brokers", "-3 brokers" or "3.5 brokers" against "3 brokers", and "runs every 60 brokers" against "runs every 60 seconds"; "brokers: 3" still supports "3 brokers";
  - **negation:** a unit with a negation is supported only by a source whose best-matching sentence also has one. The detected forms are exactly (`attribution._NEGATIONS`, `negated`): not, no, never, none, nor, neither, nobody, nothing, nowhere, cannot, without, unable, incapable; any word ending in "n't", where the apostrophe is "'" or one of the characters `coverage.APOSTROPHES` folds into it (section 4, "What the tokenizer may read"; any other apostrophe look-alike between two Latin letters makes the unit opaque, so it gets no candidate at all); the apostrophe-less contractions of a closed list of auxiliaries (dont, doesnt, didnt, isnt, arent, wasnt, werent, hasnt, havent, hadnt, cant, couldnt, wont, wouldnt, shouldnt, mustnt, neednt, aint, darent, mightnt, shant: a closed list because "client" and "event" also end in "nt"); the negating verbs fail(s/ed), lack(s/ed), refuse(s/d); the hedges hardly, rarely, seldom, barely, scarcely; and any of these spelled letter by letter with hyphens or dots ("n-o-t", "n.o.t"; a dot also cuts the sentence, so the pieces are judged alone). Antonyms and prepositions that invert a claim ("outside partitions", "deletes" for "keeps") are **not** detected. Negation is read on a **skeleton** (`attribution.skeleton`: every default-ignorable and format character removed, accents dropped, Greek/Cyrillic/Armenian look-alikes and Latin small capitals mapped to Latin), so a zero-width space, a soft hyphen, a Hangul filler, a combining grapheme joiner, a variation selector, an all-Greek "ΝΟΤ" or a small-capital "ɴᴏᴛ" cannot hide it (round 4; parser rewrite, round 1). The opposite direction (the source negates, the unit doesn't) is left to the verifier. This list only **withholds** candidates; it is not part of the guarantee, so a negation it misses is the verifier's to catch (section 5, "What coverage does not catch"; blind review round 2 reached `verified` with "outside partitions", "III brokers" and an always-supported verifier, which is exactly this residual; the full list of unread forms is in section 4, "Accepted residuals").

  Source sentences come from the source page's own parse, cut exactly like an answer (`coverage.source_sentences`). The best source has the highest coverage, then the most shared content bigrams, then the lowest label.
- **Verbatim support** (code): a code block unit gets a candidate only from a shown source holding it as a **whole** code element, exactly (section 4, "Code is covered only whole and exact": lines split on "\n" only, only spaces and tabs trimmed), with at least 3 non-trivial tokens (a number, or a word of two or more characters), so "a / b / c" or "port is 9" never gets one. Every inline span in an inferred prose unit must be a whole code element of the source its prose is attributed to. Code is never matched by word overlap, by token alignment, by line or by substring: each of those leaked in an earlier round ("rm -rf . /cache" for "rm -rf ./cache", a dropped guard line, a reordered loop, "sudo rm -rf /" for "sudo rm -rf /tmp/cache"). Recall cost: a command quoted from inside a prose line or from part of a block is not attributed.
- **No provenance means unsupported, with no model call (rule 2).** If no unit is model-covered, nothing is a candidate, the answer isn't a pure refusal, and no tool ran this turn, the answer is `unsupported` straight from `verify_citations`. It goes to the strict regeneration, then abstains, and no verifier call is spent on it.

#### 4.2 The ground check gates every inferred citation
- **The verifier checks the pairing, not just the claim.** `ground_check` sends the verifier the answer with every candidate written in as `[S<n>]` at the end of its unit (on its own line after a code block; `attribution.annotate`). `ground_check@3` says a labelled sentence is supported only if *that* source states it. The verifier's verbatim claims are mapped back onto the client's text, and a claim that was nothing but a marker makes the verdict unlocated. No extra model call.
- **Claim-level gate.** A candidate survives only if all of these hold:
  - the verdict was **conclusive** and not `unsupported`;
  - the verdict was **located**: every flagged claim is an exact substring of the answer, and `partially_supported` named at least one;
  - no flagged claim overlaps the candidate's unit.

  Survivors are emitted as `TurnCitation(hit, inferred=True)`, after the model's own citations. A dropped candidate's unit is residue.

#### 4.3 Bidirectional controls, RTL and blank glyphs (whole-answer checks)
Bidi embeddings, overrides, isolates and marks (U+061C, U+200E/200F, U+202A-202E, U+2066-2069) change what the reader SEES ("ton" displays as "not", "9092" as "2909"). They are therefore never stripped like invisible fillers. A unit holding one is opaque, so it gets no inferred citation and is residue even under a model label. At ANSWER level, any bidi control anywhere makes the whole answer residue, so it is never `verified`. The answer-level rule is needed because a control in a unit that states nothing is dropped by segmentation, yet still reverses the rest of its paragraph. Accepted residual: strong right-to-left LETTERS (Hebrew, Arabic) can reorder adjacent numbers without any control character. This is documented, not yet enforced.

### 5. Verification status (Status)
The rules below are evaluated in order (`attribution.settle`). R is the residue computed with the surviving inferred citations, **plus every model-labelled unit whose code is not whole and exact in a cited page** (`Attribution.code_unbacked`, section 4). "Covered" means at least one unit is covered by a valid model label or a surviving inferred citation; a `code_unbacked` unit is not covered. G is the ground-check verdict.

| # | condition | status | `unsupported_claims` |
|---|---|---|---|
| 0 | the whole answer is an allowlisted refusal (+/- pleasantries, labels ignored) | `unverified`, no ground check, **no citation shown** (its labels are dropped: it makes no claim, so it has no provenance; review round 2) | none |
| 1 | an invalid label (lenient or canonical, on any unit including an orphan label run or a label citing a code block), a citation-shaped fragment, **or a canonical marker the reader sees that is not a label** (escaped, struck through, in a link's text, in a URL-shaped word, inside an autolink or a linkified URL, with or without linkify: section 4), or strict mode and an unlabeled prose unit that is not allowlisted | `unsupported` → strict regeneration, then abstain | offending units |
| 2 | nothing model-covered (a `code_unbacked` unit is not covered), no candidates, no tool ran | `unsupported` (no ground-check call) | the uncovered units, `code_unbacked` ones included |
| 3 | G = unsupported | `unsupported` (no inferred citation) | the verifier's claims |
| 4a | after the gate nothing is covered, no tool ran, **and the gate was closed** (verdict inconclusive or not located) while candidates existed | `unverified`, **no citation shown** | the verifier's claims + R |
| 4b | after the gate nothing is covered, no tool ran (otherwise) | `unsupported` | the verifier's claims + R |
| 5 | G = verified, located, covered, **R = ∅** | `verified` | none |
| 6 | otherwise (G = partial, R ≠ ∅ including a `code_unbacked` unit, an unlocated verdict, or a tool turn with nothing covered) | `partial` | the verifier's claims + R |
| 7 | the model fails the verifier SLO (`verifier_trusted=false`) | rules 5 and 6 become `unverified`; **no inferred citation is shown** | unchanged + every inferred unit |

- **Labelled code is checked like inferred code (`code_unbacked`).** A label does not make altered code true: a code block cited by a label line, or a labelled sentence with inline spans, whose code elements are not all whole and exact in one of the cited sources (section 4: lines split on "\n" only, so a Unicode line separator never stands in for a line break; the dedent is the common leading-whitespace string, so re-indenting with mixed tabs and spaces never matches), is residue (highlighted, never covered). With nothing else covered the answer is `unsupported` (rule 2); otherwise `partial` (rule 6).
- **`verified` ⇒ R = ∅, by construction.** Rule 5 is the only way to `verified`, and it requires an empty residue. The guarantee therefore doesn't depend on the verifier: with a verifier that always says "supported", every residue-bearing answer still ends `partial`, `unverified` or `unsupported`. A hypothesis property checks this against the test's own residue oracle (section Tests).
- **Tool turns** are exempt from rule 2 and rule 4b (their text rests on tool results, which the ground check sees), never from the residue: "Sure." after a tool ran is `partial`, and a reply is `verified` only when `[T<n>]` labels cover it. An action reply is never page-attributed.
- **Why rule 4a keeps the answer.** ADR-0011 maps a malformed verdict to `partial` so that a formatting glitch doesn't discard a possibly good answer. Rule 4a keeps that promise for the A1 failure mode without showing unchecked provenance: the units had lexical support and the verifier refuted nothing it could point at, so the answer is shown with no citation and everything highlighted. `unverified`, not `partial`, because nothing in it was verified (review round 2). With a valid model citation an inconclusive verdict is still `partial` (rule 6).
- **Why rule 7 drops inferred citations (review round 4).** An inferred citation's only gate beyond lexical overlap is the verifier, and a verifier below its SLO can't certify server-made provenance. The model's own valid labels are still shown.
- **Inferred citations can reach `verified`**: every unit is covered by model labels or by inferred citations that had lexical (or verbatim) support **and** passed a conclusive, located verifier. The `inferred` flag, not the status, tells the reader the model didn't cite it itself.
- **What coverage does not catch.** A lexically supported fabrication (one that recombines the source's own words and numbers) gets a candidate, and only the ground check can catch it (rules 3, 4 and 6). A model label on a fabricated sentence is likewise the verifier's to catch. Coverage guarantees that nothing reaches `verified` **without** a citation or an allowlisted reason; it does not make the verifier right.
- **Strict mode (`strict_citations=True`) runs on the coverage units.** `check_citations` iterates `coverage.segment`, so "one label per sentence" means one label per **unit**: a tail after a label ("X [S1]. it was built by NASA.", "X [S1] — and NASA built it.") is a unit of its own and is offending in strict mode (it used to pass rule 1 and be caught only by the residue). Allowlisted units (a pleasantry, a refusal) and code blocks need no label (uncited code is residue, so `partial`); a label citing a code block is validated like any other. Rule 1 fires before attribution can help, and the residue rule applies on top, so strict mode is never weaker than the default. Letting inferred citations satisfy strict mode was rejected: they are only known to be valid after the ground check, which rule 1 runs before.
- **One definition of a unit, of code and of a label.** The check, strict mode, normalisation (`structure.Structure.label_spans`), stray fragments (`coverage.visible_runs`), attribution's reading of source pages (`coverage.source_sentences`, `structure.Structure.code`) and the residue all read the same CommonMark parse (section 4). The unused helpers `citations.sentence_spans`, `has_label`, `stray_fragments` and `carries_citation` are deleted (parser rewrite, review round 2).

### 6. Latency
The happy path is unchanged: `generate` + `ground_check`, two model calls. Normalisation, segmentation and attribution are pure functions over at most k sources (≪ 1 ms per sentence; a test bounds a 40-sentence answer over 8 large sources at < 50 ms). **Every scan is linear in the draft** (review round 2, P1): the inline-code regex `` (`+).*?\1 `` was cubic in a backtick run (10 s at 10,000 backticks), the product-name check before a clause-end "(S<n>)" and the stray-parenthesis regex were quadratic, merging bare label runs into one unit was quadratic, and so was matching fragments to units. They are now a 120-character window, a two-step parenthesis scan with possessive quantifiers, a cap of 8 label runs per unit, and bisections (the backtick scanner was replaced by the parser in round 4). Since round 4 the structure is one markdown-it-py parse per distinct text, cached (`structure.structure`, `coverage.segment`, `coverage.visible_runs`), so normalisation, the check, attribution and the residue of one draft share it; label spans and atoms are found by bisection, and format-character stripping has an ASCII fast path. `test_ag_perf` runs 20,000-character degenerate drafts (about 5× the longest draft seen in the evals), every repetition from **empty caches** in production order, including markdown-it-py's own worst shapes (a run of "[", emphasis and link floods, deeply nested quotes and lists): the three reviewed shapes take < 50 ms per stage, and 22 others take < 1 s for the whole pipeline (measured on the final build, cold: the slowest is 10,000 CJK sentences at about 0.4 s, most of it per-unit attribution; 20,000 "[" takes about 0.25 s, almost all of it markdown-it-py's parse); before round 2 the slowest took 4.5 to 10 s. These steps run synchronously inside async nodes, so this bound is what keeps a small model's repetition loop from stalling the shared event loop. Rule 0 *saves* the ground-check call on a pure refusal, rule 2 *saves* the ground-check call on answers that can't be shown anyway, rule 4a saves the strict regeneration when the verifier is inconclusive, and a fixed-argument command saves the tool-calling model call and the retrieval.

## Consequences
**Gains**
- **The measured winning design is now the default.** The A1 failure mode (correct, uncited) yields an answer with inferred citations instead of an abstain, for the same two model calls.
- **Small-model syntax variance no longer discards answers.** Fabricated or unshown labels are still rejected.
- **Provenance stays honest.** Every citation shown is either the model's own valid label or a server attribution that passed the lexical threshold *and* a conclusive verifier. Clients can show the difference (`Citation.inferred`).
- **`verified` has a checkable meaning.** Every character of a `verified` answer that is not positively known to state nothing is covered by a citation or by a closed, tested allowlist, and every code element is a whole, exact code element of a cited or attributed page (section 4), independent of the verifier and of how the model phrased, scripted or formatted it. What is code, what is visible and where a label is are read from a CommonMark parse, the grammar the reader's renderer shares.

**Costs and risks**
- **Paraphrase and format recall.** A correct sentence that shares few words with its source gets no citation and is residue, giving `partial`; so are a standalone "Yes.", headings, table cells and lead-ins outside the closed list (section 4). This fails closed. The thresholds are constants in `attribution.py`, to be tuned on the eval set's labelled drafts, not by intuition; the allowlist grows only with a test.
- **Lexical support is not entailment.** A negation the source lacks is now refused a candidate (section 4.1), but a fabrication that recombines source words, or a negation present in a different source sentence, still overlaps its source. Contradiction and recombination are left to the ground check, which is why an inferred citation is never shown without it, and why a verifier miss there becomes a wrong inferred citation (bounded by the verifier SLO, ADR-0012).
- **The pairing check is only as good as the verifier.** The verifier is now told which page each inferred sentence is paired with, but a 3B verifier may still accept a claim stated only in a neighbouring source. Lexical choice of the best page (highest coverage, then bigrams) makes this rare; it isn't excluded.
- **Phrasing coverage.** Phrasing detection is English and narrow on purpose. Unusual phrasings fall back to the question path, and the slash commands are the documented, reliable interface. Clients (`make ask`, UI, MCP) should surface them.
- **An extra `answer.replace`.** A streamed draft whose markers were normalised gets one `TurnReplace`, so the client sees the canonical text.
- **Coupling to the deploy setting.** Removing every tool from questions means "what does my sync status say?"-style questions work only when phrased as an action (or via `/sync`).

**Settings**
- `RAGFORGE_AGENT_MAX_TOOL_ROUNDS=0` now also disables explicit actions. The A1 `.env` override should be removed once this ships.
- `RAGFORGE_AGENT_TOOL_MODE` (`actions` | `always`) needs a config field; see `docs/handoff/P2B-AG.md`.

- **(a) The A1 failure mode:** a correct, uncited draft gives inferred citations, `verified`, and exactly `["stream", "json"]` model calls.
- **(b) Fabricated sentences:**
  - **Never cited:** a fabricated, number-drifted or negated sentence never gets a citation. It drives `partial` even when the verifier misses it, including a short one ("The port is 9093.").
  - **Non-Latin:** an uncited non-Latin answer is never `verified`. There's no verifier call, then a strict regeneration, then an abstain.
  - **Verifier gate:** a verifier-flagged, inconclusive or unlocated verdict leaves no inferred citation. An inconclusive verifier keeps the answer as `unverified`, with everything highlighted and no third model call.
  - **Malformed and wrongly paired labels:** a drifted number behind a malformed label is rejected and abstains. A wrongly paired inferred citation that the verifier flags is dropped.
  - **End to end:**
    - a tail after the last label (". it…", " — and…", "; …") is `partial`, with exactly that tail highlighted;
    - "Yes. <claim>." is `partial` with "Yes." highlighted, while "Yes, <claim>." is `verified`;
    - a pure refusal is `unverified` with one model call;
    - "No, it doesn't cover that." is `unsupported` with no verifier call;
    - with `verifier_trusted=false`, no inferred citation is emitted.
- **(c) Model and inferred citations are distinct end to end:** in `TurnCitation` and in the API `Citation` mapping.
- **(d) Tool binding:**
  - no tools on a question, even with an injected page and a model that emits a destructive call;
  - `/remove` binds only `remove_from_index` and still interrupts for approval, and its reply step runs under `action_reply@1` (`calls[1].system`);
  - fixed-argument commands are built by the server (`/remember` makes no tool-calling model call; `/forget` still interrupts for approval with no model call at all);
  - an action reply is never attributed to a page;
  - database and Kafka questions about "the index" or "the ISR" are not actions;
  - a remember turn can't reach `remove_from_index`;
  - the quote gate holds;
  - a weak grade doesn't swallow an action;
  - a command on a follow-up turn skips `contextualize` and retrieves with the command's argument;
  - Kafka/Postgres replication questions about "sync status" or "last sync" are not actions;
  - the round-4 false positives ("delete stale documents from the search index", "forget what I said, …", "show me my sources of truth for …", "Remember that Redis is single threaded?") are not actions;
  - a server-built command (`/sync`, `/sources`, `/remember …`) retrieves nothing and emits no `TurnSources`; with `max_tool_rounds=0` it is a question and retrieves.
- **(e) Lenient label parsing:** parametrised forms (including ranges), non-citation prose (including mid-clause `[1, 2]`) left byte-identical and not offending, malformed fragments offending, and a hypothesis property (with malformed forms in its alphabet) that no accepted label is outside the shown set and every sentence with a citation-shaped bracket is validly cited or offending. The property fails when the stray-fragment rule is removed.
